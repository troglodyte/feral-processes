# Delete the TUI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the `feral-processes-tui` crate and its two launcher
fallback paths, leaving the macroquad GUI as the only renderer.

**Architecture:** A pure deletion plus a rewiring of the one binary that
consumed it. `crates/tui` has no reverse dependencies in code — nothing
imports it except `crates/launcher/src/main.rs`. The no-display preflight
check survives but now fails with a readable error instead of selecting a
text renderer; the GUI-panic `catch_unwind` fallback is removed entirely.
Six doc comments in `gui` and `app-core` name the departing crate and get
corrected.

**Tech Stack:** Rust 2024 edition (rustc 1.95.0), Cargo workspace, macroquad
0.4. The `crossterm` 0.29 and `ratatui` 0.30 dependencies leave the tree with
`crates/tui`.

## A note on TDD

There is no failing-test-first cycle in this plan, and inventing one would be
theatre. This change deletes 2,388 lines that have zero tests and rewires a
binary whose only behavioural surface is "did the process start a window or
print an error." A unit test over `graphics_available()` would have to mutate
process-global environment variables, which is exactly the wall-clock/global-
state flakiness the project bans.

What replaces it, and is enforced at both task gates:

1. The **433-test invariant** — proof that nothing depended on the deleted crate.
2. **`cargo build --workspace`** — proof the workspace still resolves.
3. **A real headless run** — `DISPLAY= WAYLAND_DISPLAY= cargo run -p feral-processes`
   exercises the one changed code path end to end and needs no display, so it
   is verifiable in this environment rather than by launching the GUI.

- [ ] **Step 6: Rewrite the launcher**

Replace the entire contents of `crates/launcher/src/main.rs` with:

```rust
//! The `feral-processes` binary. Resolves the game's on-disk paths and hands
//! off to the graphical frontend (`feral-processes-gui`) — this crate itself
//! draws nothing and knows nothing about game rules.

use std::io;
use std::path::PathBuf;

use feral_processes_app_core::App;

fn main() -> io::Result<()> {
    let crate_dir = PathBuf::from(env!("CARGO_MANIFEST_DIR"));
    let repo_root = crate_dir
        .parent()
        .and_then(|p| p.parent())
        .unwrap_or(&crate_dir)
        .to_path_buf();
    let assets_dir = repo_root.join("assets");
    let saves_dir = repo_root.join("saves");
    std::fs::create_dir_all(&saves_dir)?;
    // One-time migration: earlier builds kept a single save at
    // `save.bin`. Move it into the new saves directory (under its old
    // name) so it still shows up in the load list instead of silently
    // disappearing — even if it turns out to be from an incompatible
    // save version, it's still visible there and deletable.
    let legacy_save = repo_root.join("save.bin");
    if legacy_save.exists() {
        let _ = std::fs::rename(&legacy_save, saves_dir.join("save.bin"));
    }
    let history_path = repo_root.join("run_history.log");

    if !graphics_available() {
        eprintln!("No display detected; feral-processes needs a graphical display.");
        std::process::exit(1);
    }
    feral_processes_gui::run(App::new(assets_dir, saves_dir, history_path));
    Ok(())
}

/// Best-effort preflight check: on Linux there's no windowing system to
/// open a window on at all without an X11/Wayland display, and macroquad's
/// underlying platform layer aborts the process rather than returning a
/// catchable error in that case — so this check is what turns the common
/// "no display" case (e.g. an SSH session or a CI box) into a readable
/// error instead of a raw abort. macOS/Windows always have a compositor
/// available to the active session, so there's nothing analogous to check.
fn graphics_available() -> bool {
    #[cfg(target_os = "linux")]
    {
        // An empty (but present) value is what a shell like `DISPLAY= cmd`
        // produces, and behaves the same as unset here — `var_os` alone
        // would treat it as "present" and skip straight to a doomed
        // XOpenDisplay() call.
        let has = |name: &str| std::env::var(name).is_ok_and(|v| !v.is_empty());
        has("DISPLAY") || has("WAYLAND_DISPLAY")
    }
    #[cfg(not(target_os = "linux"))]
    {
        true
    }
}
```

Five things changed and each is deliberate:

1. The module doc's third sentence (the one calling the TUI "the fallback
   renderer for the no-display/GUI-crash cases below") is gone, because those
   cases are gone.
2. `use std::panic::{self, AssertUnwindSafe};` is gone. `use std::io;` stays —
   `main`'s `io::Result<()>` return type still needs it, because
   `std::fs::create_dir_all(&saves_dir)?` still propagates.
3. The no-display branch uses `eprintln!` + `std::process::exit(1)`, **not**
   `return Err(io::Error::other(..))`. `Termination` for `Result<T, E>` prints
   the error's `Debug` form, and `io::Error`'s `Debug` for a custom error is a
   struct dump — measured output was
   `Error: Custom { kind: Other, error: "No display detected; …" }`, which is
   not a message anyone wants. `process::exit` skips destructors, which costs
   nothing here: only a few `PathBuf`s are live.
4. `graphics_available`'s docstring no longer says "this check, not
   `catch_unwind`, is the fallback path that actually fires." It kept its
   *reason for existing* (macroquad aborts uncatchably) and changed only its
   description of what happens on failure.
5. `feral_processes_gui::run` returns `()` (see `crates/gui/src/lib.rs:108`),
   so it is called as a statement and `main` ends with `Ok(())`. The three
   `.clone()` calls on `assets_dir`/`saves_dir`/`history_path` are gone —
   they existed only so the removed fallback branch could build a second
   `App`, and each value is now used exactly once.

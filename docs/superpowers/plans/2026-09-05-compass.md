# The compass — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to work this task by task. Steps use
> checkbox syntax for tracking.

**Goal:** A selected destination and a live bearing to it — a picker on `u`
listing the home base, recorded settlements and Stack entrances, and a
one-line strip on the zone map's bottom border pointing at the choice.

**Architecture:** One engine derivation (`Game::compass_targets`) in
`Game::attention`'s shape, one saved selection resource, one new `Mode`
with a scrolling read-only screen, and one border strip. Every target is
already recorded and saved; this feature adds one bool, one resource and
one screen, and reads what is already there.

**Tech stack:** Rust, `bevy_ecs` 0.19 standalone in the engine, RON saves
via serde, `bevy_egui` behind `paint::Painter` in gui.

**Spec:** [`docs/superpowers/specs/2026-09-05-compass-design.md`](../specs/2026-09-05-compass-design.md).
Read it first — it carries the eight decisions and the alternatives each
beat. This plan argues from it and does not restate them.

## Global constraints

- **No `SAVE_FORMAT_VERSION` bump.** Both save changes are additive behind
  `#[serde(default)]`. If you find yourself needing a bump, stop — the
  design is wrong, not the constant.
- **No `resources::GameRng` draw anywhere in this feature.** It is a
  derivation over recorded state; a draw would shift every later roll in
  the run.
- **`bearing(dx, dy)` (`crates/engine/src/game/stack.rs:63`) is reused, not
  reimplemented.** It is `pub(crate)`; widen it if the derivation lives
  outside `game::stack`. A second bearing formula is the exact "doc comment
  claiming to mirror other code" failure CLAUDE.md names.
- **Lowercase letters are row selectors.** On the zone map lowercase is the
  convention (`a`–`x` are bound there); on any screen with rows, a new
  action must be UPPERCASE.
- **Commits on this branch stay unversioned.** The version bump, the
  `CHANGELOG.md` section and the tag happen once, at the merge.
- Gates: `cargo fmt`, `cargo clippy --workspace`, and
  `cargo test --workspace` before calling anything done. Iterate with
  `cargo test -p feral-processes-engine <name>`.

## Two traps that will cost you an afternoon

**1. Registering a new Resource shifts bevy's query iteration order.** If
`cargo test --workspace` fails in a subsystem you never touched right after
Task 2 inserts `CompassBearing`, that is a *latent unsorted-query test*
surfacing, not your regression. Confirm by stashing only the
`insert_resource` line; then fix the test's incidental coupling, not your
resource.

**2. `-p feral-processes-engine` and `--workspace` are different builds and
shift the seeded RNG stream.** The seed-1788625345 fixture in Task 6 must
be run under **both** before you believe it.

## Task 2: `Game::compass_targets` and the saved selection

**Files:**
- Modify: `crates/engine/src/game/inspection.rs` (beside `Game::attention`, `:1459`)
- Modify: `crates/engine/src/resources.rs` (`CompassBearing`)
- Modify: `crates/engine/src/game/lifecycle.rs:271, :555` (both insert sites)
- Modify: `crates/engine/src/save.rs:1124-1171, :1647`
- Test: `crates/engine/src/tests/` — a new `compass.rs`, registered in `tests/mod.rs`

**Consumes:** `CompassTarget`, `KnownSettlement::visited` (Task 1).

**Produces:**

```rust
pub struct CompassRow {
    pub target: CompassTarget,
    pub label: String,             // name if visited, else a generic noun
    pub bearing: &'static str,
    pub distance: Option<i32>,     // None while unvisited
    pub visited: bool,
}

impl Game {
    pub fn compass_targets(&mut self) -> Vec<CompassRow>;
    pub fn compass_bearing(&mut self) -> Option<CompassRow>; // the selection, resolved
    pub fn set_compass_bearing(&mut self, target: Option<CompassTarget>);
}

pub struct CompassBearing(pub Option<CompassTarget>);       // Resource, serde(default)
```

The two tiers land **only** in `label` and `distance`, so the rule is
stated once in the engine and no surface re-decides it.

Sources, all already saved: home from `Game::anchor_position()`
(`game/stack.rs:348`) and **always `visited: true`** — it is the party's
own; settlements from `resources::Settlements`; links
from `SurfaceLink` entities. A link is visited iff `resources::StackMemory`
holds any key whose `.0` equals its tile — `FrameKey` is
`((i32,i32), u32)` and its doc (`resources.rs:1462`) says it is keyed by
the link's surface tile, so this needs no new field.

Ordering: home, then settlements, then links; each group nearest-first.
`attention`'s rule, so "the first row" is stable across runs without a
second sort.

- [ ] **Step 1** — Write the failing tests. Intent, one test each:
      ordering is home → settlements → links, nearest-first within each;
      an unvisited settlement yields `distance: None` and a label that is
      **not** its name; a visited one yields both; `compass_bearing()`
      returns `None` when the selection names a link that no longer exists;
      `compass_targets()` is empty in `Locale::Stack` and in
      `Locale::Base`.
- [ ] **Step 2** — Run them; expect failures on the missing methods.
- [ ] **Step 3** — Implement. Widen `stack::bearing` to `pub(crate)` reach
      if needed. The empty-off-surface case is a single early return on the
      `Locale` read, not a filter per row.
- [ ] **Step 4** — Tests pass. **If unrelated suites now fail, read trap 1
      above before changing anything.**
- [ ] **Step 5** — Add `SaveData::compass` behind `#[serde(default)]`, save
      and load it. Write **two** tests: a RON round-trip and a
      `Game::save` → `Game::load` test. The round-trip alone stays green
      through a `#[serde(skip)]` slip, which is why both are required.
- [ ] **Step 6** — `cargo test -p feral-processes-engine compass`, then
      `cargo test --workspace`. Commit.

## Task 5: the strip on `map_pane`'s bottom border

**Files:**
- Modify: `crates/gui/src/render/hud/layout.rs:184` (`map_pane`), and the test
  at `:330-348` whose doc says the bottom border carries nothing
- Modify: `crates/gui/src/render/base.rs` (draw the strip)
- Test: both files

**Consumes:** `Game::compass_bearing()` (Task 2).

The rule (CLAUDE.md, "The HUD"): a pane whose border carries a strip starts
its body at `render::hud::layout::strip_inset` and **buys the height for
it**, because the strip's quad reaches as far into the pane as out of it.

**Buy it unconditionally.** Buying it only while a target is selected
resizes the map the instant one is picked, which reads as a camera fault. A
few pixels of map, always, in exchange for a stable viewport.

Content: `» Lowport · south · 219` visited, `» a settlement · south`
unvisited. Absent when nothing is selected, and absent off the zone
surface — which falls out of `compass_bearing()` returning `None`, not from
a second `Locale` check here.

- [ ] **Step 1** — Write the failing tests: `map_pane`'s body height is
      **identical** with a target selected and with none; the strip renders
      both forms; the strip is absent with no selection and absent
      off-surface; nothing paints over it (mirror
      `base.rs::nothing_paints_over_the_vitals_strip`).
- [ ] **Step 2** — Run; expect failures.
- [ ] **Step 3** — Implement. Update the doc comment at `layout.rs:330`,
      which currently states the bottom border carries nothing — that
      sentence becomes false in this task and is load-bearing for the next
      person.
- [ ] **Step 4** — `cargo test -p feral-processes-gui`. Commit.

# Siege Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new event in which the sector's wild programs walk in through the base's one door, steal what they can carry, wreck what they cannot, and withdraw on a morale break — fought on a tactical board built from base space itself.

**Architecture:** Five seams. **The clock** is `resources::SiegePressure`, `RaidPressure`'s shape and not that resource, accrued in its own `Game::siege_check` beside `raid_check`. **The board** is `siege::board::build` — a flood fill from `BASE_EXIT_CELL` through `BaseGrid::walkable`, seated in the bounding box of the fill, handed to `TacticalBattle::open` instead of `map::generate`. That is the one place a siege departs from every other tactical fight, and it is why a siege does **not** go through `Game::start_battle` or `fights_tactically` at all. **The raiders** are ordinary spawned bodies carrying `components::Besieger`, which is the third kind of body holding a base-space `Position`; their steal/wreck/withdraw behaviour is one hook ahead of the generic tactical AI, gated on that component. **Turrets** are a `StructureDef` field resolved at a point in the round, holding no initiative slot. **The save** is assembled from the board, never derived by serialising `TacticalBattle`, with membership riding `CreatureSave` the way a sortie's does.

**Tech Stack:** Rust, `bevy_ecs` 0.19, RON assets, `serde`.

**Spec:** `docs/superpowers/specs/2026-09-22-siege-design.md` — read it before Task 1. Its §1–§10 are the contract; its "Decisions taken in dialog" records what each was chosen *over*, and none of them is open for re-litigation by an implementer.

## Two corrections to the spec, stated up front

Neither changes a decision; each changes a file list or a claim.

1. **§5 says a siege is "always tactical, regardless of the profile toggle", which reads as a change to `fights_tactically`. It is not one.** `Game::fights_tactically` (`crates/engine/src/game/combat.rs:398`) gates on the profile toggle, `require_surface().is_ok()` and the absence of a `NestGuardian`. A siege fails the surface gate outright and must ignore the toggle, so routing it through `start_battle` means widening a predicate three other encounter kinds read. The siege opens its own door instead — `Game::open_siege` builds a board and calls `TacticalBattle::open` directly — and `fights_tactically` is **not edited**. `App::opened_battle_mode` already reads `Game::in_tactical_battle` rather than the toggle, so the screen follows for free. Task 8.

2. **§4 says structures "stand on their anchors as obstacles that can be attacked". They cannot be attacked by the path that exists.** A swing resolves through `Game::apply_damage`, which is the only door that damages a *creature* and wants `Stats`; a `Structure` has `Durability` and no `Stats`, so a swing aimed at one either panics or silently does nothing. Structure damage on the board routes to `Game::damage_structure` (`game/base/upkeep.rs:898`) through an explicit branch, which is also what makes "a structure destroyed in a siege is destroyed the way any other one is" true. Task 10.

## Global constraints

- **No `save::SAVE_FORMAT_VERSION` bump.** It is 32 (`crates/engine/src/save.rs:1632`) and stays there. Every new save field is additive behind `#[serde(default)]`; a save written before this loads as "no siege in progress", which is what that run is. Do not recapture `dev-saves/` for the format.
- **`TacticalBattle` does not gain `Serialize`.** It is bare `#[derive(Resource)]` (`crates/engine/src/tactical/mod.rs:90`) *specifically* because a fight is never saved. Bolting `Serialize` on makes every fight saveable and the first symptom is a Stack battle surviving a reload with its board intact. `SiegeSave` is **assembled** from the board and the bodies by a free function. Task 16 carries a test that an ordinary tactical fight is still not saved.
- **One new `Resource` only** — `resources::SiegePressure`. A new resource shifts bevy's query iteration order across the whole engine, which this repo has recorded as a cause of seeded tests moving; the in-progress siege lives in `TacticalBattle` plus components, not in a second resource.
- **The siege never touches the sweep.** `RaidPressure`, `raid_check`, `run_raid`, `RAID_*` and the sweep's warning line are read-only reference material. The one shared surface is `StructureDef::raid_defense`, which a turret keeps paying into.
- **Every new tuning value is a documented `pub const` in `crates/engine/src/tuning.rs`**, in a new `// Sieges` section placed after `// Base & raids` (which begins at `tuning.rs:2689`). No magic numbers in a formula, and no `.ron` value duplicated into it.
- **Turret behaviour is a `.ron` question.** The engine names no turret id, ever. Whether a turret needs power, staffing or ammunition is authored on the def.
- **Vocabulary.** The event is a **siege**; the attackers are **besiegers** in player-facing text. "Sweep" stays the GC Entropy Sweep's word and is never used for this; "raid" remains the code's word for the sweep. The engine type is `components::Besieger`.
- **Gates before every commit:** `cargo fmt`, then `cargo clippy --workspace --all-targets` (`--all-targets` is load-bearing — a bare run leaves test modules unlinted), then the task's own tests via `cargo test -p feral-processes-engine <name>`. `cargo test --workspace` is the gate at the end of each phase only.
- **Do not bump the workspace version or write a `CHANGELOG.md` section on this branch.** That happens once, at the merge.
- **Playtesting is the user's.** Agents cannot run the game here. Every number in this feature is reasoned from the tick rate, not measured; say so rather than claiming a siege plays well.

## The tick rate, and every number derived from it

The sweep is the anchor: `RAID_PRESSURE_THRESHOLD = 4800` against an accrual of `RAID_PRESSURE_PER_ZONE (1) * zone`, which at sector 2 is 2400 ticks, and the changelog states that as "every fifteen to twenty-five minutes". **Two ticks a second.** Every siege constant below is stated in minutes first and derived from that, never the other way round.

| constant | value | what it means |
|---|---|---|
| `SIEGE_PRESSURE_PER_ZONE` | `1` | `level += SIEGE_PRESSURE_PER_ZONE * zone` a tick, the sweep's accrual shape |
| `SIEGE_PRESSURE_THRESHOLD` | `14_400` | 60 min at sector 2, 20 min at sector 6 |
| `SIEGE_PRESSURE_JITTER_PERCENT` | `25` | 45–75 min at sector 2; **one draw on the target** |
| `SIEGE_PRESSURE_WARN_PERCENT` | `80` | 12 min out at sector 2 |
| `SIEGE_WARN_FLOOR_TICKS` | `960` | 8 min, the wall-clock floor §2 exists for |
| `SIEGE_MIN_ZONE` | `2` | gates **accrual**, never firing |
| `SIEGE_PACK_BASE` | `4` | plus `SIEGE_PACK_PER_ZONE (1) * zone`, capped at `SIEGE_PACK_MAX (12)` |
| `SIEGE_MORALE_BREAK_PERCENT` | `50` | half the pack down and the rest withdraw |
| `SIEGE_STAFF_DEFENSE` | `2` | each on-shift staff body's contribution to the off-screen defence |
| `SIEGE_STEAL_PER_POINT` | `4` | units lifted off the shelves per unanswered point |
| `SIEGE_DAMAGE_PER_POINT` | `3` | structure `Durability` lost per unanswered point |
| `SIEGE_POINTS_PER_CASUALTY` | `10` | one staff body killed per this much shortfall |

The percentage window governs sectors 2–3 and the floor governs 4 and deeper; the crossover is at an interval of 4800 ticks, which is exactly sector 3. **The floor's value is unvalidated** — nothing in this repo models the walk home from a deep Stack frame — and the seam entry written in Task 18 must say so.

# Phase 1 — The event exists

At the end of this phase a siege fires on its own clock, warns first, and resolves off-screen against the base's defences. There is no board yet: **every** siege resolves off-screen, including one the player is home for. That is a deliberate temporary state, closed in Task 8, and Task 4's tests must not assume it is permanent.

### Task 1: The clock

**Files:** Create `crates/engine/src/game/siege/{mod.rs,clock.rs}`, `crates/engine/src/tests/siege.rs`. Modify `resources.rs` (beside `RaidPressure` at :1803), `tuning.rs` (new `// Sieges` section after :2689's block), `save.rs` (`SaveData`, beside `raid_pressure: RaidPressure` at :1489), `lifecycle.rs` (`init_resource` at :552 and :1303, restore near :1568, write near :2737), `game/turn.rs` (the call, immediately after `self.raid_check();` at :358), and the `mod` declarations.

**Interfaces — produces:**
- `resources::SiegePressure { pub level: u32, pub next_at: Option<u32>, pub warned: bool }`, deriving exactly what `RaidPressure` derives.
- `Game::siege_check(&mut self)` — `pub(crate)`.
- `Game::siege_pressure(&self) -> u32` — `pub`, `raid_pressure`'s counterpart at `upkeep.rs:490`.
- `Game::dev_force_siege(&mut self)` and `Game::dev_wind_siege_clock(&mut self)` — `pub`, consumed by Task 5.
- `tuning::SIEGE_PRESSURE_PER_ZONE`, `SIEGE_PRESSURE_THRESHOLD`, `SIEGE_PRESSURE_JITTER_PERCENT`, `SIEGE_MIN_ZONE`.

**Shape.** `siege_check` follows `raid_check`'s body order (`game/base/upkeep.rs:496-572`) and departs from it in exactly one place, marked below:

1. `if zone < SIEGE_MIN_ZONE { return; }` — the gate is on **accrual**. Gating firing lets the opening sector bank pressure it cannot spend and ambushes the player the instant they cross.
2. Lazily draw `next_at` through a private `draw_siege_interval(&mut self) -> u32`, jittering `SIEGE_PRESSURE_THRESHOLD` by `±SIEGE_PRESSURE_JITTER_PERCENT` in **one** `random_range` draw. Per-tick jitter averages out to a metronome and costs a draw a tick besides.
3. Accrue.
4. The warning (Task 2 — leave a `// Task 2` stub here that does nothing).
5. `if level < target { return; }`.
6. **The departure from `raid_check`:** the hold. `raid_check` holds on `defending_base_staff_count() < RAID_MIN_BASE_STAFF`; a siege holds when **any of** there being no base (`Game::base_is_established`), nothing standing to besiege, or another fight already running (`Game::in_battle` / `Game::in_tactical_battle`) is true. Each is a `return` **before** the reset, so the pressure is still owed.
7. Fire, then `level = 0; warned = false; next_at = None;` — and only if the fire reported that a siege actually happened, the `if !self.run_raid() { return; }` pattern at `upkeep.rs:568`.

For this task the fire is a private `fn stage_siege(&mut self) -> bool` that logs one line and returns true. Task 4 replaces its body with the off-screen resolution and Task 8 puts the home/away branch in. It is a stub for exactly two tasks and is never left in.

**Test intent** (`tests/siege.rs`, every one seeded):
- Sector 1 accrues nothing at all, and crossing into sector 2 does not arrive carrying banked pressure.
- A tick that decides a siege happens but cannot stage one — no base — leaves `level` at or above its target rather than zeroing it, and the very next tick with a base fires. One test per hold.
- The interval is drawn **once**: run two ticks and assert `next_at` is unchanged and the RNG stream advanced by exactly one draw across the pair. A stable target passes against one that re-draws and discards, so compare the stream, not the field.
- A siege in sector 6 comes at three times the rate of one in sector 2, asserted on tick counts, not on constants.

**Gates:** `cargo fmt`; `cargo clippy --workspace --all-targets`; `cargo test -p feral-processes-engine siege`. Commit.

### Task 2: The warning and its floor

**Files:** Modify `crates/engine/src/game/siege/clock.rs`, `tuning.rs`, `crates/engine/src/game/inspection.rs` (the attention derivation read by `Game::attention`).

**Interfaces — produces:** `Game::siege_warned(&self) -> bool`; `tuning::SIEGE_PRESSURE_WARN_PERCENT`, `SIEGE_WARN_FLOOR_TICKS`.

**Consumes:** Task 1's `SiegePressure` and the stub at step 4 of `siege_check`.

**Shape.** The latch is the sweep's (`upkeep.rs:534-550`): set `warned` once, log one line through `log_base_kind(MessageKind::Raid, …)`, and add one attention row that stays up until the siege lands. The one difference is *when* it fires. The sweep warns at a share of its drawn interval; the siege warns at **whichever is earlier**, a share of the interval or a fixed number of ticks out:

```rust
let by_share = target * SIEGE_PRESSURE_WARN_PERCENT / 100;
let accrual = SIEGE_PRESSURE_PER_ZONE * zone;          // never zero: the gate above
let by_floor = target.saturating_sub(SIEGE_WARN_FLOOR_TICKS * accrual);
let warn_at = by_share.min(by_floor);
```

`by_floor` is in *pressure*, not ticks, which is the whole subtlety: the floor is a wall-clock promise and the meter is not a clock, so it converts through the accrual rate before it can be compared.

**Test intent:**
- At sector 2 the share governs and at sector 6 the floor does, each asserted as **ticks between the warning and the siege**, not as a pressure figure — the point of the floor is wall-clock and a test in pressure units would pass against a broken conversion.
- The deep-sector window is at least `SIEGE_WARN_FLOOR_TICKS` and the shallow one is longer than it.
- The line is logged once across many ticks. `message_history` condenses repeats, so sum `repeats` or the assertion is vacuous.
- The attention row is present from the warning until the siege and absent before and after.

**Gates:** as Task 1. Commit.

### Task 4: The off-screen siege

**Files:** Create `crates/engine/src/game/siege/offscreen.rs`. Modify `tuning.rs`.

**Interfaces — produces:**
- `Game::resolve_siege_offscreen(&mut self) -> bool` — `pub(crate)`, false when there was nothing to besiege (which is Task 1's hold). It replaces Task 1's `stage_siege` stub.
- `siege::pack_size(zone: u32) -> u32` — `SIEGE_PACK_BASE + SIEGE_PACK_PER_ZONE * zone`, capped at `SIEGE_PACK_MAX`. It lives here rather than in Task 8 because the off-screen siege and the fought one must field the same pack, and a second expression of that is the first thing to drift.
- `tuning::SIEGE_PACK_BASE`, `SIEGE_PACK_PER_ZONE`, `SIEGE_PACK_MAX`, `SIEGE_STAFF_DEFENSE`, `SIEGE_STEAL_PER_POINT`, `SIEGE_DAMAGE_PER_POINT`, `SIEGE_POINTS_PER_CASUALTY`.

**Consumes:** `turret_defense` (Task 3), `Game::total_raid_defense` (`upkeep.rs:267`), `Game::defending_base_staff_count`.

**Shape.** This is **not** `run_raid`'s body — a sweep is one machine taking one hit, and an abstract siege prices all four stakes. One shortfall figure, three payouts:

```
strength  = pack_size(zone)
defence   = total_raid_defense() + turret_defense() + staff * SIEGE_STAFF_DEFENSE
shortfall = strength.saturating_sub(defence)
```

then, in this order: `shortfall * SIEGE_STEAL_PER_POINT` units lifted from base shelves; `shortfall * SIEGE_DAMAGE_PER_POINT` `Durability` spread over machines through `Game::damage_structure`, which is what makes a structure destroyed off-screen destroyed the way any other one is; `shortfall / SIEGE_POINTS_PER_CASUALTY` staff killed through the door a Forgiving death already uses, `Game::bench_or_dissolve`.

**It reports as an event, not as a number.** The log names what was taken and what was broken, the way a town raid names its author — one `MessageKind::Raid` line per stake that actually moved, and nothing at all for a stake that did not.

**Test intent:**
- One test per stake: stores gone, a machine damaged, a structure destroyed outright when the damage exceeds its remaining `Durability`, a staff body benched.
- **A defended base loses strictly less than an undefended one** with the same pack — the "not cheaper than defending" property, asserted as a comparison between two runs rather than against a constant, since a constant moves with a retune and the ordering must not.
- A shortfall of zero costs nothing and logs nothing.
- `pack_size` grows with the sector and stops at `SIEGE_PACK_MAX`.
- The whole resolution spends no `GameRng` draw, asserted by comparing the stream — a deterministic payout is what lets Task 8's on-screen fight be the only place a siege rolls.

**Gates:** as Task 1. Then `cargo test --workspace` and commit the phase.

### Task 7: The flood fill

**Files:** Create `crates/engine/src/game/siege/board.rs`.

**Interfaces — produces:**
```rust
pub(crate) struct SiegeBoard {
    pub board: Board,
    pub origin: (i32, i32),   // base-space cell of board (0, 0)
    pub door: (i32, i32),     // BASE_EXIT_CELL in board coordinates
}
pub(crate) fn build(game: &mut Game) -> Option<SiegeBoard>;
impl SiegeBoard {
    pub(crate) fn to_board(&self, base: (i32, i32)) -> Option<(i32, i32)>;
    pub(crate) fn to_base(&self, cell: (i32, i32)) -> (i32, i32);
}
```

**Consumes:** `BASE_EXIT_CELL` (`game/base_space.rs:29`), `BaseGrid::walkable` (`base_grid.rs:127`), `Game::structure_tiles` (`game/zone.rs:409`), `Board::solid`/`set` (Task 6).

**Shape.** Flood-fill four-ways from `BASE_EXIT_CELL` through `BaseGrid::walkable`; the bounding box of the fill is the board, its `side` the longer edge, the remainder of a non-square fill left `Blocked`. `BaseGrid` solid rock is `Blocked` and is never breached, so the fill's frontier *is* the board's wall — there is no separate wall pass. Laid floor is `Open`. **A sealed-off pocket is not in the fill and so not in the fight**: a player who walls off their far works has genuinely protected them, and that falls out of the fill rather than being checked for. `None` when the door cell itself is not walkable, which is a base that does not exist.

Structure anchors are **not** written into the board as cells — they are seated as bodies in Task 8, because a `Blocked` cell cannot be attacked. Read a structure's footprint through `Game::structure_tiles`, never by restating the derivation.

**Test intent:**
- Rock reads `Blocked` and laid floor `Open`, on a base with a known cut.
- A pocket of floor with no walkable path to the door is absent from the board — build a grid with a deliberate gap and assert the pocket's cells are `Blocked`.
- `to_board`/`to_base` round-trip for every cell of a fill, and `to_board` answers `None` outside the box.
- The door is in bounds and `Open`.
- A single-cell base yields a 1x1 board rather than `None` or a panic.

**Gates:** as Task 1, `cargo test -p feral-processes-engine siege`. Commit.

### Task 8: Opening a siege

**Files:** Modify `crates/engine/src/game/siege/mod.rs`, `crates/engine/src/game/siege/clock.rs` (the fire branch), `tuning.rs`.

**Interfaces — produces:**
- `Game::open_siege(&mut self) -> bool` — `pub(crate)`.

**Consumes:** `siege::pack_size` (Task 4) — **called**, never restated, or the siege you fight and the siege you miss are different sizes; `SiegeBoard` (Task 7), `Game::habitat_pools` (`spawning.rs:1754`), `Game::spawn_pack` (`spawning.rs:1834`), `Game::base_bodies` (`zone.rs:444`), `Game::base_pos` (`game/stack.rs:387`), `TacticalBattle::open` (`tactical/mod.rs:189`), `place` (:229), `set_shape` (:285).

**Shape.** `siege_check`'s fire becomes: if the player is in base space (`base_pos().is_some()`), `open_siege`; otherwise `resolve_siege_offscreen`. Both return `bool` and both feed the same reset.

`open_siege` builds the board, mints a `BattleSpec` for it — `TacticalBattle::open` takes one — with `site` the anchor, `biome` the player's own tile's, `bodies` the seated count, and then **ignores `BattleSpec::side()` entirely**, since the board is built. Then:

- **Every body in base space is seated where it already stands.** Nobody is deployed; the base's arrangement at the moment the siege opens is the opening position, which is the payoff for making the base the board. Walk `Game::base_bodies` and `place` each at `to_board` of its `Position`; a body whose cell is outside the fill (a program adopted on the surface that has not drifted) is simply not seated.
- **The player and their party** are seated at `base_pos`, taking the door-adjacent free cells if the player's own cell is contested.
- **Structures** are seated as bodies too, with `set_shape`'s footprint taken from `structure_tiles`, and are left **out of `initiative`** — they are obstacles that can be attacked (Task 10), not combatants.
- **Raiders** enter at the door. `BASE_EXIT_CELL` is the single entrance and the Home stands on it; one body to a cell means they file in. Spawn `pack_size(zone)` bodies from `habitat_pools` at the sector's danger band — the same derivation a wild pack spawn already uses, no new species content — mark each with `Besieger` (Task 11), and seat them at and behind the door.
- **`fights_tactically` is not edited and `start_battle` is not called.** A siege is always tactical, whatever the profile toggle says.

**Test intent:**
- With `Profile::tactical_battles` **off**, a siege still opens a `TacticalBattle`.
- A posted program standing at its machine is on the board at that cell; nothing was moved to open the fight.
- The player is on the board and their party with them.
- Raiders are all at or adjacent to the door at round 1.
- The number of raiders seated equals `pack_size(zone)` — the same call Task 4 prices with.
- A siege does not open while another fight is running — the hold, asserted through `siege_check` rather than `open_siege`.

**Gates:** as Task 1, plus `cargo test -p feral-processes-gui` (the render path reads the toggle at `render/tactical.rs:1085` and `:1160`; **check those two reads do not hide a siege's board when the toggle is off**, and fix them to read `Game::in_tactical_battle` if they do). Commit.

### Task 9: A body with nothing in reach takes no turn

**Files:** Modify `crates/engine/src/tactical/turn.rs` (around `hand_on_turn` at :1401).

**Interfaces — produces:** `Game::tactical_body_is_engaged(&self, body: Entity) -> bool` — `pub(crate)`.

**Shape.** `TacticalBattle` documents that a fight holds at most thirteen bodies and keeps its body list as a linear-scanned `Vec` on that basis; a developed base holds a hundred. The mitigation is that a body with nothing in reach **takes no turn at all** — it is on the board, it can be attacked, it will act the moment something is near it, but it does not consume a turn to decide to stand still. The order thins to the bodies actually in contact.

`tactical_body_is_engaged` answers true when any body of the opposing side is within `reach::movement_field(battle, body, allowance)` plus `Game::swing_range(body)`. The skip is applied in the hand-on, and only to bodies the AI drives — **never to the player or their party**, whose turn is the player's to spend as they like.

Two guards, both load-bearing:
- **The skip must not be able to empty the order.** If no body in the whole order is engaged, skip nobody; otherwise a siege where the two sides have not met yet spins forever.
- The skip is re-evaluated every time the cursor reaches a body, never cached, because the thing that makes it engaged is another body walking toward it.

This is a design constraint, not an optimisation, and it has a visible consequence the implementer must accept rather than fix: **a body four rooms from the fighting does not walk toward it.** Staff do not reinforce; they defend where they are.

**Test intent:**
- A staff body across the base from the fighting is passed over, asserted by the round advancing without its `actions_left` being spent.
- The same body acts on the round a raider comes into reach.
- A board on which nobody is engaged still advances its rounds rather than hanging — the guard, and the test that would catch an infinite loop.
- The player is never skipped, even alone on the board with nothing in reach.

**Gates:** as Task 1, `cargo test -p feral-processes-engine tactical siege`. Commit.

### Task 10: Structures are attackable

**Files:** Modify `crates/engine/src/tactical/turn.rs` (the swing resolution).

**Shape.** A swing whose target carries `Structure` routes to `Game::damage_structure` (`upkeep.rs:898`) and returns; every other target keeps its existing path through `Game::apply_damage`, which stays the only code path that damages a *creature*. A structure holds no initiative slot, so there is nothing to hand the turn on to when one is destroyed — but it **is** on the board, so its removal has to take its cells with it through `TacticalBattle::remove`.

**Test intent:**
- A swing at a machine lowers its `Durability` and does not panic on the missing `Stats`.
- A machine destroyed on the board is destroyed the way any other one is — the same log line and the same teardown as `damage_structure`'s other callers, asserted by reading the world rather than the log alone.
- A destroyed structure's cells become walkable and the fight continues.
- Nothing about the initiative order moved when it died.

**Gates:** as Task 1. Then `cargo test --workspace` and commit the phase.

# Phase 3 — What raiders do

### Task 11: `Besieger` and its citizenship

**Files:** Modify `crates/engine/src/components.rs`, `crates/engine/src/game/inspection.rs` (`stands_in_base_space` at :407, `entity_label`). Create `crates/engine/src/game/siege/raiders.rs`.

**Interfaces — produces:** `components::Besieger` (a unit marker).

**Shape.** A besieger is the **third kind of body carrying a base-space `Position`**, after a posted program and a `DigSite`. That seam already records that `Structure` no longer answers "which space is this?" on its own, and this sharpens it. Three consequences, each an edit:

- `Game::stands_in_base_space` gains a `Besieger` arm, which is what keeps a raider off the surface map — **the map draws one space and that function is which**.
- `Game::entity_label` gains an arm, or a besieger examines as "You" the way a `Trap` did before its arm existed.
- The wild-population systems must not count or cull a besieger: check `ensure_local_population`, `cull_to_cap` and `maybe_spawn_wild_creature` for queries that would pick one up, and narrow them on `Without<Besieger>` where they do.

**Test intent:** a besieger is absent from the surface map's entities and from the examine ray on the surface; it is present on the base map; the wild population count does not move when a siege opens; `position_is_honest` (whatever form that check takes in the suite) still passes.

**Gates:** as Task 1. Commit.

### Task 12: They steal

**Files:** Modify `crates/engine/src/game/siege/raiders.rs`, `tuning.rs`, `crates/engine/src/tactical/ai.rs` (the one hook).

**Interfaces — produces:** `Game::besieger_turn(&mut self, body: Entity) -> bool` — true when it acted, false to fall through to the generic tactical AI.

**Shape.** One hook, at the top of the actor path in `tactical_ai_turn` (`ai.rs:323`), gated on `Besieger`. The behaviour is opportunistic — no quota, no objective cell, no timer:

- Adjacent to a shelf or a machine's buffer with something in it → take what it can carry and make for the door. **Carrying is the hauler's one `(item, qty)` pair reused** (`components::Carrying`, `components.rs:810`) — a raider is a body carrying something, and the cap is what keeps that one pair honest. Reuse the hauler's existing carry-cap constant; do not mint a second.
- Carrying already → walk toward the door.
- At the door carrying → leave the board and **what it carried is gone**. A step off the board edge is already a departure rather than a refusal, so a raider leaving is the mechanism that exists.
- **Killed while carrying → the goods drop**, back into the structure it was taken from if that still stands, else onto the floor as a pickup. This is what makes interception the shape of the fight rather than a race, and it is the single most load-bearing line in the task.

**Test intent:**
- A raider beside a stocked Depot leaves the board with units that are gone from the base's stock afterwards.
- A raider killed one cell short of the door drops what it held, and the base's total stock is unchanged across the whole episode.
- A raider with nothing in reach to take does not stand still — it falls through to the generic AI.
- The carry cap bounds one raider's haul, asserted against the shared constant rather than a literal.

**Gates:** as Task 1. Commit.

### Task 13: They wreck

**Files:** Modify `crates/engine/src/game/siege/raiders.rs`.

**Shape.** One more arm, below the steal arms: adjacent to a machine with **nothing to take** → swing at it, through Task 10's branch. Nothing new about the damage; the whole task is the priority order, which is steal before wreck, because a raider that wrecks the shelf it could have emptied makes interception pointless.

**Test intent:** a raider beside an empty machine attacks it; a raider beside a stocked one steals instead; a base with nothing worth taking anywhere is still wrecked rather than stood in.

**Gates:** as Task 1. Commit.

### Task 14: They withdraw

**Files:** Modify `crates/engine/src/game/siege/raiders.rs`, `tuning.rs`.

**Shape.** When `SIEGE_MORALE_BREAK_PERCENT` of the pack is down, the rest withdraw: the door arm becomes unconditional for every besieger, carrying or not. **A withdrawal is not a rout to chase** — a raider that leaves is gone, with whatever it was carrying.

The fight then ends by one of the endings the tactical model already knows: the roster emptied (`FightVerdict::won`, which is the roster *emptied* and never "nothing is alive" — a withdrawal empties it exactly as a kill does), the party gone, or the player jacking out. **There is no quota and no round limit**, and the fight's length tracks how fast the defence kills, which was chosen over a quota with that trade-off stated.

**Test intent:**
- Downing half a pack sends the rest to the door, asserted on the survivors' cells moving doorward over rounds.
- A pack that fully withdraws ends the fight as a win, through the same verdict a wipe produces.
- The withdrawn raiders' cargo is gone from the base.
- Below the threshold nobody withdraws.

**Gates:** as Task 1. Commit.

### Task 15: Turrets fire

**Files:** Modify `crates/engine/src/game/siege/turrets.rs`, `crates/engine/src/tactical/turn.rs` (the round wrap).

**Interfaces — produces:** `Game::fire_turrets(&mut self)` — `pub(crate)`, called once at the start of each round.

**Shape.** A turret fires once a round at the **nearest hostile in range with line of sight**. It has no `Stats`, no initiative slot and no body: it is a property of a structure, resolved at a point in the round. Line of sight is the board's, through `reach::line_of_sight` (`tactical/reach.rs:310`) — never a second copy of the test. Damage lands through `Game::apply_damage` on the target, since the target is a creature.

**Test intent:**
- A turret in range kills or damages the nearest besieger at the round's start, and the initiative order's length did not change.
- A turret with no line of sight to the only hostile fires at nothing.
- A turret out of range fires at nothing.
- Two hostiles at different distances: the nearer is hit.
- A destroyed turret stops firing.

**Gates:** as Task 1. Then `cargo test --workspace` and commit the phase.

# Phase 4 — Saving a siege

### Task 16: `SiegeSave`

**Files:** Create `crates/engine/src/game/siege/persist.rs`. Modify `save.rs` (`CreatureSave` at :328 — the `#[serde(default)] pub sortie_index: Option<u32>` at :373 is the pattern; `SaveData` at :1175), `lifecycle.rs` (the load context's deferred fields at :205-217, its destructuring at :1497, the apply site beside `restore_sorties` at :1512, and the write side beside `sortie_index:` at :2092).

**Interfaces — produces:**
- `save::SiegeSave` — a **named struct, never a positional tuple**: `spec: BattleSpec`, `side: i32`, `cells: Vec<BattleCell>`, `origin: (i32, i32)`, `door: (i32, i32)`, `round: u32`, `turn: u32`, `actions_left: u8`.
- `CreatureSave::siege_cell: Option<(i32, i32)>` and `CreatureSave::siege_order: Option<u32>`, both `#[serde(default)]`.
- `SaveData::siege: Option<SiegeSave>`, `#[serde(default)]`.
- `siege::persist::assemble(game: &Game) -> Option<SiegeSave>` and `siege::persist::restore(game: &mut Game, saved: SiegeSave, members: &[(u32, Entity, (i32, i32))])`.

**Shape.** The precedent is the sortie and it is exact. `TacticalBattle` holds `Entity` values and entity ids are not stable across a save, which is why a sortie's membership rides `CreatureSave::sortie_index` and `SortieSave` carries no member list. A siege does the same: each body's board cell and its place in the initiative order ride `CreatureSave`; `SiegeSave` holds only what is not per-body.

**`assemble` builds the save from the board and the bodies. It does not serialise the resource**, and `TacticalBattle` does not gain `Serialize` — a `Serialize` bolted onto it would quietly make every fight saveable and the first symptom would be a Stack battle surviving a reload with its board intact.

Restore is **deferred**, through the load context that already carries `sortie_members`, `pending_cronjobs`, `pending_patrols` and `pending_study` (`lifecycle.rs:205-217`): collect `(siege_order, entity, siege_cell)` while creatures load, and rebuild the `TacticalBattle` after, beside `restore_sorties` at `:1512`. A record whose members all failed to load is **dropped**, not restored empty.

**Verify before writing:** whether `components::Carrying` already round-trips through `CreatureSave`. A hauler's carried pair must already survive a save; if it does not, add it here behind `#[serde(default)]`, because a besieger killed after a reload must still drop what it was holding.

**Test intent:**
- A **real save→load round trip with a siege in progress** — pack the RON back into a `.bin` through the real door. A RON round trip alone leaves a `#[serde(skip)]` green and proves nothing. Assert board cells, every body's cell, and the initiative order all survive, and that the fight can be continued after the load.
- A save written before this feature loads as "no siege in progress" and the run plays on.
- **An ordinary tactical fight is still not saved** — open one, save, load, assert there is no `TacticalBattle`. This is the invariant test and it must fail if `Serialize` is ever added to the resource.
- A besieger carrying cargo across a save still drops it when killed after the load.
- `SAVE_FORMAT_VERSION` is still 32.

**Gates:** as Task 1, plus `cargo test -p feral-processes-engine save_roundtrip`. Then `cargo test --workspace` and commit the phase.

## What this plan does not do, and does not want done

Out of scope, from the spec and not to be helpfully added: a second base entrance; breaching rock; a defence-roster screen; authored GC species; sieges anywhere but the base; a siege the player can decline. Also: no `balance_sim` term — it has no raid term and no siege term, and every number here is reasoned from the tick rate rather than measured, which is the same blind spot the raid clock's seam already records.

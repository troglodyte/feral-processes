# Outposts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-tile fixture on the zone surface where posted programs extract materials, growing from raw to processed to complex yields. The output comes home by caravan route or by hand, and the outpost can be raided.

**Spec:** `docs/superpowers/specs/2026-09-23-outposts-design.md`. Read it before Task 1. Where it disagrees with the corrections below, the corrections win: they were checked against the source.

**Shape:** six phases, each one dispatch-sized, ending green and committed, so a session can `/clear` between phases and restart from this file. Phases 1–2 are the engine core. Phase 3 is the screen and the map. Phase 4 is routes, 5 is raids and alerts, and 6 is content and docs. Phases 4 and 5 are independent of each other.

## Corrections to the spec (found by checking the source)

1. **`Outpost` is the seventh `ProgramRole`, not the sixth.** `UnderStudy` shipped between `Sortie` and `Staff` (`game/party.rs:20`). Add `Outpost` after `Sortie` in `role_of`'s chain (`party.rs:83`), before the `under_study` check. `role_of` gains a `posted_at_outpost: bool` parameter. The `Roles` SystemParam (`party.rs:150`) gains a presence query `Query<(), With<components::PostedAt>>`, `under_study`'s pattern, and it is **not** a new `Res`. `Game::program_role` (`party.rs:957`) passes `get::<PostedAt>().is_some()`. The three exhaustive matches are `roster_rank` (renumber: `Outpost` sits between `Sortie` and `UnderStudy`), gui's `role_heading` (`render/party.rs:289`) and `turn.rs:1381` (`=> false`).
2. **The role audit is the `UnderStudy` census.** Run `rg -n 'UnderStudy' crates/engine/src -g '!tests/**'`. Every site that *excludes* a pinned program needs the same exclusion for `PostedAt`: `programs_for_build` (`party.rs:~766`), `fuse_companions` (`party.rs:1280`), `commit_program`, and any other hits. Four doors check neither and need an explicit refusal: `wield_program` (`party.rs:1006`), the party add, `extract_routine` (`routines.rs:720`) and `open_kernel_ring` (`refactor.rs:230`). The doors that already filter on `== Staff` refuse for free: `dispatch_sortie` (`sortie.rs:243`), `pin_subject` (`study.rs:258`), `needs_drain_system` (`systems.rs:107`) and entropy. Each still gets a refusal test.
3. **`PendingVisit` is not serialized** (`resources.rs:2109`). `Visit` needs no serde, and it has no save change. Rename `Game::take_settlement_visit` (`game/spawning.rs:1263`) to `take_visit() -> Option<Visit>`. Its one app-core caller is `app/playing.rs:701`.
4. **`Route` is not `Serialize`, and `RouteSave::destination` is not optional** (`save.rs:309`). So the spec's `Route::outpost: Option<_>` plus an accessor becomes the following. In memory, `Route`'s three destination fields collapse into `destination: RouteEnd`, with `RouteEnd::{Settlement { key, def, tile }, Outpost((i32, i32))}`, because `Route` is free to change. `RouteSave` is **untouched**. Outpost routes save as a new `SaveData::outpost_routes: Vec<OutpostRouteSave>` behind `#[serde(default)]`. That is additive, with no version bump.
5. **`Record::Acquire` never folds into `base_ledger`** (`telemetry.rs:165`). An outpost cycle reports as `base_ledger::Event::Extract { item, rolled, landed, ok }`, the event the base output page already folds into MINED. Mirror the record closure the base's extract call site passes. A by-hand take into the pack is an `Acquire` with a new `LootSource::Outpost` (`base_ledger.rs:121`, with an `as_str` arm).
6. **`mining_success_chance` takes scalars** (`systems.rs:251`): `(level, keen_scavenger_level, base_int, morale, strain)`. Call it with `0.0, 0.0` for the last two. The class-based yield bonus lives in `resolve_gather_cycle` and is bound to a node, so **v1 applies no class bonus at an outpost**. That settles spec §11's open item: record it in the `tuning.rs` section doc, not as a TODO.
7. **Outposts are records, so they are drawn and examined like settlements, not through `drawn_on_surface_map`.** That function is about entities. Follow the code path that draws and examines a `resources::Settlements` tile.
8. **Two flat spatial constants break the aid-radius seam.** `MAX_BUILD_DISTANCE_FROM_HOME` is a base-space constant (value 4), and the spec reused it for a zone-surface distance. Use a new `OUTPOST_MIN_ANCHOR_DISTANCE`. That and `OUTPOST_MIN_SPACING` are both written as fractions of `settlements::placement::REGION_TILES`, and each gets a test that it is reachable (`a-gated-consequence-can-be-green-and-unreachable`).
9. **Raids ride the sweep clock, not a roll per tick.** `raid_check` (`upkeep.rs:497`) accrues pressure, and `run_raid` fires when the pressure reaches its threshold. Outposts roll inside that same firing branch, after the base resolves. The `RAID_MIN_ZONE` gate therefore applies, so **outposts in zone 1 are never raided**. That is intended; state it in the help page.
10. **The alert board shipped** (`alerts.rs`). Append `AlertKind::{OutpostStale, OutpostDeclining, OutpostDark, OutpostRaided}`. The variant names are save format, so append them and never reorder. The subject is `format!("outpost@{x},{y}")`. The latch for announcing only on a change is a `#[serde(skip)]` field `announced: Option<Trend>` on `Outpost`, **re-seeded to the current trend on load**, so a reload doesn't post an alert again.
11. **Transfer's commit is hard-wired to depots** (`app-core/src/app/transfer.rs:50` calls `game.transfer_items`). Add `App::transfer_source: TransferSource::{Base, Outpost((i32, i32))}`, set by the opener and read by `commit_transfer`. Outpost rows are `can_put: false`. The engine door is `Game::take_from_outpost(tile, &basket)`.
12. **`ALL_MODES` is 116 now** (`gui/src/render/mod.rs:1515`). This plan adds two modes, `OutpostVisit` and `OutpostPost` (the staff picker for `[P]`), which takes it to 118.

## Global constraints

- Every save addition is `#[serde(default)]`: `SaveData::outposts`, `SaveData::outpost_routes` and `CreatureSave::outpost`. No `SAVE_FORMAT_VERSION` bump, and don't recapture `dev-saves/`. Each field gets a **real `Game::save` → `Game::load` test**: a RON round trip passes against `#[serde(skip)]`.
- The new `Outposts` resource shifts bevy's query iteration order. **Budget one pass for seed-luck tests moving** in Task 2 (see the memory `rng-stream-shift-exposes-seed-luck-tests`). Fix each test so it no longer depends on luck. Never change the seed.
- No `GameRng` draw while no outpost stands. One test per phase that touches the tick asserts this, predation's pattern.
- Outposts are processed in `BTreeMap` key `(x, y)` order.
- Every refusal lands before anything is spent or changed, and is asserted per refusal.
- Item ids are content. The Rust code names no item id; the def names them.
- Gates before every commit: `cargo fmt`, then `cargo clippy --workspace --all-targets`, then the task's tests. Run `cargo test --workspace` at the end of each phase.
- Deleted-fix check on every refusal test and every omission test: remove the guard and watch the test fail.
- No version bump or CHANGELOG *section* on the branch. The CHANGELOG entry text is drafted in Phase 6 under the existing convention.
- Never push.

## Phase 1 — Def, record, placement, save

### Task 1: `OutpostDb` and the def

- `OutpostDef { name, glyph: char, kit: ItemId, repair_cost: Vec<(ItemId, u32)>, tiers: Vec<OutpostTierDef>, features: Vec<()> }`. `OutpostTierDef { yields: BTreeMap<Biome, Vec<ItemId>> }`. Put `#[serde(default)]` on every field except `tiers`. `features` stays empty and reserved (spec §10). Pick the type that parses `[]` and change it when a feature lands. Don't design it now.
- `OutpostDb::load_dir`, `StructureDb::load_dir`'s pattern: a malformed file is skipped with a warning, and a missing directory is an empty db. `OutpostDb::def() -> Option<&OutpostDef>`: v1 has one def, and the first by filename wins.
- `yields(def, tier, biome) -> Vec<ItemId>`: the union of tiers `0..=tier`, each using the biome's row or falling back to that tier's **first** listed biome row (`BTreeMap` order). Sort and dedupe.
- Ship a minimal `assets/outposts/outpost.ron` using existing item ids, so the engine tests have a def to load. Phase 6 replaces the item picks.
- [ ] Tests: loader skip and absent behaviour; the union includes the lower tiers; the fallback for an unlisted biome; an empty db means `def()` is `None`.

### Task 2: record, `found_outpost`, kit, save

- `Outpost` as in spec §2, plus the `#[serde(skip)] announced` field from correction 10 (it is inert until Phase 5). `Outposts(BTreeMap<(i32, i32), Outpost>)` as a `Resource`, inserted in `Game::new`.
- `Game::found_outpost(tile) -> Result<(), String>` with the refusals from spec §9, using correction 8's constants and `MAX_OUTPOSTS`. The Stack link, nest and settlement checks reuse the existing occupancy queries. Find them; don't restate them.
- In `use_item`, **before** `consume_item`: if `id` is the def's `kit`, call `found_outpost` at the player's `Position`, take one kit on `Ok`, and send `Err` through `note_refusal`. An absent db refuses with a message. Check that app-core's inventory `use` key (`app/inventory.rs:305`) is not gated on `consume.is_some()`. If it is, widen the gate through a `Game::is_usable(id)` query, never an item-id check in app-core.
- Save: `SaveData::outposts: Vec<OutpostSave>`, a named struct carrying the tile and the stored fields. Load re-seeds `announced` (a no-op until Phase 5).
- [ ] Tests: one per refusal (the kit is still in the pack afterwards). A success places a record with the biome read at the tile. Save → load keeps every field. Two outposts save and load in key order. **Then run the full suite and fix seed-luck tests** (Global constraints).

## Phase 2 — Crew, growth, production

### Task 3: the role and the doors

- `PostedAt(tile)` component, plus corrections 1 and 2.
- `post_to_outpost(tile, creature)`: refuse unless a visit to that tile is the one the player is standing at (the player's `Position` is adjacent to the tile), the program is `Staff`, it isn't `Downed` or `Carrying`, and the crew is below `OUTPOST_CREW_CAP`. On success, first free any `Task` the program holds, the same way pinning a subject does (read `study.rs:~298` and copy its order). Then insert `PostedAt`.
- `recall_from_outpost(creature)`: remove `PostedAt`, then set the base-space position to the entry tile the Stack's downed-program arrival uses. Find that arrival path. Don't write a new one.
- `outpost_crew(tile) -> Vec<Entity>`, sorted by `ProgramId`: one query, reused by every reader.
- `bench_or_dissolve` and `dissolve_tamed_program` remove `PostedAt`. `fuse_companions` refuses outright (correction 2).
- Save: `CreatureSave::outpost: Option<(i32, i32)>`. Load re-inserts `PostedAt`. Resolve it **after** `Outposts` is restored, and drop a membership whose tile has no record (log it).
- gui: the `role_heading` arm is `"Posted at an outpost"`.
- [ ] Tests: each refusal on each audit door. The role of a posted program. Omissions: it is not in `base_staff()`, and the needs drain doesn't touch it. The rest-repair `false` arm. Recall returns the program to `Staff`. Save → load keeps the crew, and an orphaned membership is dropped.

### Task 4: trend, growth, production

- `outposts::tier(&Outpost, crew) -> usize` and `outposts::trend(&Outpost, crew, tier, stock_cap) -> Trend`, pure, from spec §4's table with the first match winning. `Trend::reason(...) -> String`, built in the engine.
- The tuning constants from spec §3 go in `tuning.rs`'s `// Outposts` section, each with a doc comment. The values are placeholders and should say so.
- `Game::run_outposts()` from `tick_inner`, following spec §5 exactly. Place it next to `run_routes` and give the reason for the position in a comment. Per crew roll, call `mining_success_chance` (correction 6). Pick the item with one `GameRng` draw only when the union has more than one entry. Emit `Event::Extract` (correction 5).
- A dark outpost (integrity 0, which Phase 5 can produce) skips production and growth. Put that check here now.
- [ ] Tests: every row of the trend table, plus the order of the first match. Growth is kept when crew is short, and the tier drops to what the crew can hold. `stale_ticks` accumulates and resets. The draw happens only when the union has more than one entry. **No `GameRng` draw with no outposts.** Stock stops at the cap. A ledger `produced` count rises. A seeded run of N cycles is deterministic.

## Phase 4 — Route endpoint

- `RouteEnd` (correction 4). Every existing reader of `destination`, `destination_def` and `destination_tile` goes through a match. Settlement behaviour is unchanged, and the existing route tests are the gate.
- `run_routes` (`game/route.rs:344`), outpost arm: the outbound leg carries nothing and sells nothing. On arrival it moves up to `ROUTE_OUTPOST_CARRY` units from the outpost's stock into `cargo`, taken in `ItemId` order. The inbound leg's predation rolls on `cargo` with `settlements_near_route` and `preys_on_routes`, the same way the goods of a settlement route are handled. Read what predation takes there today and keep that shape. It lands through `return_material`. If the record is gone, the route is `stalled` with one log line, and it retries on each tick like any stall.
- Dispatch goes through `dispatch_reach` unchanged. The cargo picker lists known outposts as destinations, and its preview is "hauls up to N", not `route_quote`.
- Save: `OutpostRouteSave` with named fields.
- [ ] Tests: a round trip brings the stock home. The carry is capped. Predation on the goods is seeded. A gone outpost stalls the route. A standing route reloads. Save → load. **No new draw** when nothing preys.

## Phase 5 — Raids, repair, alerts, attention

- In `raid_check`'s firing branch after `run_raid`, one roll per outpost in key order, from spec §8's formula (correction 9). The chance is clamped below 1 by a named constant. On a hit, the crew member benched is the **first by `ProgramId`**, which is deterministic and spends no extra draw. `bench_or_dissolve` already posts `ProgramDowned`.
- At zero integrity: recall every crew member through `recall_from_outpost`. It stays on the map as dark.
- `repair_outpost(tile)`: pays `repair_cost` from the pack, refuses whole before a unit moves, and restores full integrity. Wire `[R]`.
- Alerts (correction 10): post on a trend transition into `Stale` or `Declining`, on going dark, and on a raid hit. Post only on the transition. `Game::attention` gains a row per outpost in `Stale`, `Declining` or dark.
- Outposts never enter `open_siege` or `resolve_siege_offscreen`. One test asserts a siege leaves the outposts untouched.
- [ ] Tests: a seeded hit applies damage, the steal fraction and one bench. Crew lowers the chance. A hostile town raises it. Zone 1 is never raided. A dark outpost's crew is back on staff. Repair refusals and success. Each alert posts once, and holding the same state posts nothing more. A reload doesn't post again. There are attention rows. **No draw with no outposts.**

# Drop pods — plan

Spec: `docs/superpowers/specs/2026-09-27-drop-pods-design.md`. Branch
`drop-pods`, worktree `../feral-processes-drop-pods`. TDD inline, a commit
per green step; each phase ends on `cargo test --workspace` + clippy
`--all-targets` + fmt.

## B1 — the terminal and its charge (engine + one gui mark)

Recharge is `Upgrade`'s path with a different completion arm. Read the
`Upgrading is a build request too` bullet in
`seams/references/base-structures.md` first — its five traps are this
phase's checklist.

1. **Schema.** `structures::DropPodDef { recharge_cost: Vec<(ItemId, u32)> }`
   and `StructureDef::drop_pod: Option<DropPodDef>`, `#[serde(default)]`,
   documented in `dispatches_sorties`' "a flag, never the id" terms.
   `assets/structures/README.md` row.
   *Test:* a def without the field parses as `None`; with it, the bill.
2. **Content.** `assets/structures/drop_pod_terminal.ron` (`footprint: 2`,
   no `upgrade`, no `work` → costs no program by `runs_a_job`), and
   `assets/research/drop_pods.ron` with `unlocks_structures:
   ["drop_pod_terminal"]`, `requires: ["dispatch"]`, `min_zone: 2`, a
   materials bill that passes the research-bill census. Recharge bill
   `[("core_fragment", 2), ("cache_grain", 1)]`.
   *Gate:* `cargo test -p feral-processes-engine assets` (all censuses).
3. **Component.** `components::DropPod { charged: bool }`, inserted by
   `spawn_structure` when `def.drop_pod.is_some()`, charged.
   *Test:* a raised terminal carries `DropPod { charged: true }`.
4. **Save.** `StructureSave::pod_charged: Option<bool>`, `#[serde(default)]`;
   write it where the structure record is built, restore it after
   `spawn_structure` in the structure restore. Absent → charged.
   *Tests:* save→load (not RON-only) of a spent pod stays spent; a record
   with the field absent loads charged.
5. **Goal.** `BuildGoal::Recharge`; fix every exhaustive match the compiler
   names — `program_tier_required` (→ 1, never reached: no program is
   committed), `BuildOrderRow::label` (`"{name} — recharging"`),
   `building.rs`' log lines, `restore_build_sites`' Glyph gate (born
   without one — the terminal is still standing and drawing itself; make
   the gate `goal == New` stay true only for `New`). `count_build_requests`
   already filters `== New`.
6. **Filing.** `Game::spend_pod(terminal) ` (pub(crate)): sets
   `charged = false` and spawns `BuildSite { goal: Recharge, program: None,
   cost: def.drop_pod.recharge_cost }` on the terminal's anchor, unless a
   site already stands there. Logs once. B2's `call_reinforcement` is the
   caller; B1 tests call it directly.
   *Tests:* exactly one site, the def's bill, `program: None`; spending
   twice files one.
7. **Completion.** `raise_one_tick`'s `Recharge` arm: resolve the structure
   by tile (Upgrade's query), set `DropPod::charged = true`, `consume_site`,
   free the worker's `Task`, log. Missing machine → leave the site
   (Upgrade's precedent).
   *Tests:* driving the crew to completion charges the pod and spawns no
   second structure; the site is gone; the materials are spent.
   *Mutation:* delete the `charged = true` write → test fails.
8. **Cancel** needs nothing new (`cancel_build_request` refunds; pod stays
   spent). *Test:* cancel leaves `charged: false` and refunds delivered
   units.
9. **Map mark (gui).** `EntityView` (or the structure's view row) gains
   `pod_charged: Option<bool>`; `render/base.rs` draws a spent terminal's
   glyph dimmed (`palette` role, not a literal colour). Screenshot check
   via `--screenshot` if a display is present; otherwise say so.

## B2 — the routine and the drop

Facts from the survey (verified 2026-09-27; re-check line numbers):

- Routine nodes: `routine_tree::synthesise_nodes`, `requires` is
  `Vec<ResearchId>` only — **no structure gate exists**. Recommended: give
  `call_reinforcements` an ordinary ungated synthesised node; `NoPodReady`
  already makes it inert without a terminal. **Decided 2026-09-27 (user):
  ungated** — no structure-gate field on `ResearchDef`.
- `Summon` never reaches `use_ability` (`combat_round.rs` arm is
  `unreachable!`); the tactical path is the Special-site arm in
  `tactical/turn.rs` (~1345) → `seat_summon_on_board` (~1233: `place` +
  `insert_after_cursor`). `Reinforce` joins that arm the same way, and its
  `use_ability` arm is `unreachable!` too (`tactical_only()` → true keeps it
  out of the group model).
- No-aim routine: `target: WholeParty` (`fork_cluster.ron`,
  `teleport.ron`'s comment).
- `RoutineRefusal` in `game/combat.rs`; `ability_unavailable` checks Power
  **last** — the four new refusals go before it.
- `Party` cap: `MAX_PARTY_SIZE` checked in `add_companion`, load truncation,
  and revive re-insertion; `seat_summon_in_group` already pushes uncapped —
  the precedent.
- `finish_fight` (`combat_teardown.rs`): dead-party loop → `bench_or_dissolve`
  (skips `Summoned`); survivors are **left in `Party`**. Reinforcement
  teardown goes after that loop: remove every `Reinforcement` body from
  `Party` and strip the marker.
- A non-siege tactical fight is not saved (`siege::persist::assemble` →
  `None`), so `Reinforcement` needs no save field.
- `arm_status(e, StatusKind::Stun, 1, 0)`; `landed_this_round` makes it cost
  exactly the next turn.
- `is_on_shift(who, &Amenities)`; `Game::base_staff()` is Staff in
  `(StaffRank, Entity)` order — `drop_troopers()` filters it by the marker.

Steps:

1. `components::DropTrooper` marker + `CreatureSave::drop_trooper: bool`
   (`#[serde(default)]`), written/restored in both creature save paths;
   `Game::set_drop_trooper(e, bool)`; `Game::drop_troopers()`.
   *Tests:* save→load round-trip; absent loads false; order is rank order.
2. `AbilityEffect::Reinforce`, `tactical_only` → true, `use_ability` arm
   `unreachable!`; `assets/abilities/call_reinforcements.ron`
   (`WholeParty`, Power + cooldown in `fork_cluster`'s band); README; the
   ability censuses in `tests/assets.rs`.
3. Refusals `NoPodReady`, `NoTrooperAvailable`, `InSiege`, `NoLandingCell`
   before Power in `ability_unavailable`, each with its row-fragment string.
   *Test per refusal:* Power, cooldown and pod charge unchanged.
4. `Game::call_reinforcement(caster)`: candidates = `drop_troopers()` whose
   role is `Staff` and `is_on_shift`; nearest charged pod by base-space
   Chebyshev, ties by table order; `spend_pod` (B1); push to `Party`
   uncapped; insert `Reinforcement`; `place` adjacent to the player +
   `insert_after_cursor`; `arm_status` Stun 1; log via `creature_label`.
   *Tests:* closest wins; tie → rank order; sixth body in a full party;
   loses exactly its next turn; its post frees next tick.
   *Mutation:* flip the distance compare; drop the cap bypass.
5. Teardown in `finish_fight`. *Tests:* survivor back to `Staff` and
   reposted, party size restored; a dead one is benched on Forgiving;
   XP kept.
6. Group model / arena never offer it (census via `tactical_only`).

**B2 as built (2026-09-27), where it departs from the above:**

- **No `Stun`.** A stun costs no turn on a battle map (it only stops a
  walk; nothing tactical skips a stunned body). The lost first turn is
  `Reinforcement { reorienting }`, passed by `pass_reorienting_turn` from
  `hand_on_turn` beside `skip_disengaged_turns`.
- **Unposting is by hand.** The scheduler keeps an outsider's `Task` post
  covered and doesn't run mid-fight, so `call_reinforcement` strips
  `Task`/`Carrying` (`pin_subject`'s rule). A body carrying a downed
  program is not callable.
- **Landing is `Summon`'s**: the nearest free cell by a whole-board search,
  so `NoLandingCell` means a full board, not a walled-in invoker.

# World Map, Surface Fog, and Compass from the Map — plan

Spec: `docs/superpowers/specs/2026-10-08-world-map-design.md`. The spec
holds the rules and the argument. This file gives the order of work, the
files, the decisions the spec left open, and the gates. Branch: `world-map`.

**Every phase:**
- Use TDD and commit at each green step.
- Leave `cargo fmt` and `cargo clippy --workspace --all-targets` clean.
- Unset `FERAL_DEV_NO_SIEGES` before running tests.
- Never push. Never `git checkout`, `stash` or `reset` over uncommitted
  work. Stage explicit paths only (the tree has unrelated `art/` and
  `glitch.*` changes; do not touch or stage them).
- Before editing, read `.claude/rules/seams-ground.md`. Phases 3 and 4 also
  read `seams-screens.md` and `seams-hud.md`; Phase 4 also reads
  `drawing-seam.md` and `seams-help.md`.
- Phase gate: the crate tests named in the phase. Phase 4 runs the full
  `cargo test --workspace`.

The phases run in order, because each one consumes the previous phase's API.
Each phase fits one fresh subagent: hand it this file and the spec, not the
history.

## Decisions the spec left to the plan

These are verified against the source (2026-10-08).

1. **Fog hook.** Add `Game::mark_explored_chunks` and call it from
   `Game::tick_inner` (`game/turn.rs:231`), next to `ensure_local_population`
   and `ensure_local_settlements`. That one call site catches every writer
   of `Position`: walking, `place_player_at`, recall, and the footprint
   eject.
   - Gate it on `Locale::Surface`. Neighbouring calls have no guard, so
     this one needs its own.
   - Copy the shape of `ensure_local_population` (`spawning.rs:1225`).
   - Use `div_euclid(world::CHUNK_SIZE)`.
2. **Breach does not clear `ExploredChunks`.** A breach does not rebuild the
   world (seams-ground). `enter_next_zone` clears `PopulatedChunks`;
   leave `ExploredChunks` alone and test that it survives.
3. **Biome sampling.** Add a `pub(crate) WorldMap::biome_at(&self, x, y)`
   wrapper over the private pure `classify` (`world.rs:222`): three Perlin
   samples, with no chunk load. Sample the chunk's centre tile only.
   Overrides are ignored, which is acceptable at chunk scale.
4. **`world_map` takes `&mut self`, not `&self`.** It has to read outpost
   crew, nests (`nest_positions`) and `SurfaceLink`s, and all three are
   query-backed `&mut` methods. `compass_targets` is already `&mut`.
   - The view still writes nothing.
   - It must not settle commerce. It uses the shared pure function from
     item 6.
   - A test asserts that `Standings` is unchanged after a call.
5. **"Met" means present in `resources::Settlements`.** The compass already
   lists those, and labels an unvisited one "a settlement".
   - A town mark's label comes from the same function the compass uses.
   - If that label is inline in `compass_targets`, extract it so both call
     it (the call-not-copy rule).
6. **Pending drift is one pure function.** Add
   `settlements::growth::settle_commerce(relation: &Relation, epoch: u64,
   hostile: bool) -> CommerceSettle { commerce, commerce_epoch,
   commerce_at_epoch }`.
   - The decay rate is the one at `settlement_growth.rs:225`.
   - `settle_commerce_drift` calls it and writes the result through
     `adjust_commerce`, so the clamp and announcement stay in one door.
   - The view calls it and reads the result.
   - `TownTrend` comes from `trend(result.commerce,
     result.commerce_at_epoch)`. There is no threshold: compare strictly,
     and equal means `Flat`. Add a `tuning.rs` constant only if a test shows
     one is needed.
7. **Server status uses words, not numbers.** Add
   `growth::outlook(now, due) -> GrowthOutlook { Soon, InTime }`.
   - `due` is `due_tick − pull_ticks(commerce)`, as in `latch_growth`.
     Extract that expression so both call it.
   - The cut-off is a new constant, `WORLD_MAP_GROWTH_SOON_TICKS`, in
     `tuning.rs`.
   - The two strings are "Grows into a Mainframe soon." and "Grows into a
     Mainframe in time."
   - No tick vocabulary.
8. **Outpost compass.** Add `CompassTarget::Outpost((i32,i32))` at the end
   of the enum (`settlements/mod.rs:46`).
   - `compass_targets` adds an outpost group, nearest-first, after the
     links.
   - Resolution needs no new code. A lost outpost is simply absent from the
     rows, so `compass_bearing()` returns `None`. That is the collapsed-Link
     path.
9. **Routes are one straight segment.** A route runs from the anchor to
   `RouteEnd::tile()`, so "polyline" means one segment per route.
   - Name it `WorldMapRoute { from_chunk, to_chunk, preyed_by:
     Vec<SettlementKey> }`.
   - `preyed_by` comes from `Game::route_predators` (`game/route.rs:816`),
     not a re-derivation.
   - Corridor reveal: add a pure function `routes::corridor_chunks(from,
     to) -> Vec<(i32,i32)>`, a grid line over chunk coordinates, with its
     own unit test.
10. **`Mode` holds unit variants only (it is `Copy`).** Add a unit
    `Mode::WorldMap`.
    - State lives on `App`: `world_map_center: (i32,i32)`, with
      `menu_selected` reused for the row.
    - The view radius is `WORLD_MAP_VIEW_RADIUS` in app-core. The side list
      and the grid must agree on it.
11. **Keys in `WorldMap`.**
    - Arrows pan, so do **not** route through `selected_index`'s Up/Down.
    - Lowercase letters (and digits) select rows.
    - `C` sets the compass.
    - `P` re-centres on the party.
    - `Esc` closes.
12. **Opening the map.** The surface `g` is a new branch ahead of the
    Stack dispatch at `app/playing.rs:444`. The Stack-only handler at :670
    is unchanged. The existing test `g_does_nothing_on_the_surface`
    (`app-core/src/tests/stack.rs` ~:228) is inverted, not deleted.
13. **Help.** Help pages are free-form, so no new page is needed.
    - Add `g` to the surface section of `assets/help/20-controls.md`.
    - Add a short World Map key block beside the compass block (`u`, :64).
14. **Screenshot fixture.** No template has an outpost or route. Build a
    `dev-saves/world-map.ron` template:
    1. `savetool dump` the `settlements` template.
    2. Hand-add one outpost and one route, with the route passing a Hostile
       town.
    3. `pack` it, then `capture` it.
    4. Document it in `dev-saves/README.md`.
15. **New seam.** "Fog stores only where the party walked; derived reveals
    are never stored." Write it in three places, in the order the `seams`
    skill gives: the graph, the skill, and `seams-ground.md`.

## Phase 1: Stored state (engine)

**Files:**
- `resources.rs`: add `ExploredChunks(pub BTreeSet<(i32,i32)>)` beside
  `PopulatedChunks`.
- `save.rs`: add `explored_chunks` with `#[serde(default)]`. Follow
  `populated_chunks` at every site: `Game::save` (`lifecycle.rs:3369`),
  `Game::load` (:1891), `Game::new` (:603), the load preamble (:1565), and
  `sample_data()`.
- `tuning.rs`: add `WORLD_MAP_REVEAL_RADIUS_CHUNKS` and
  `WORLD_MAP_GROWTH_SOON_TICKS`.
- `game/turn.rs` and a new `game/world_map.rs`: add `mark_explored_chunks`
  (decision 1).
- `settlements/relations.rs`: add `Relation::commerce_at_epoch: i32` with
  `#[serde(default)]`.
- `settlements/growth.rs`: add `settle_commerce`, `TownTrend`, `trend`,
  `GrowthOutlook`, `outlook`, and the extracted `due` expression
  (decisions 6 and 7).
- `game/settlement_growth.rs`: make `settle_commerce_drift` and
  `latch_growth` call the pure functions.
- `settlements/mod.rs`, `game/inspection.rs`: add `CompassTarget::Outpost`
  and the outpost rows (decision 8). Extract the label if needed
  (decision 5).

**Tests:**
- Walking reveals chunks within the radius.
- Nothing is revealed in base space or the Stack.
- Fog survives a breach.
- `ExploredChunks` survives a real save→load (use `save_and_load`, not a
  RON round-trip).
- `trend` and `outlook` have unit tests.
- Across an epoch:
  - a decayed town reads `Falling`;
  - a town traded with above the decay reads `Rising`;
  - `commerce_at_epoch` survives save→load.
- `settle_commerce` output equals what `settle_commerce_drift` then writes.
- An outpost appears in `compass_targets`.
- An `Outpost` bearing resolves, survives save→load, and goes `None` once
  the outpost is removed.

**Gate:** `cargo test -p feral-processes-engine` and `balance_sim`, which
should not move. If it does, stop and report.

## Phase 2: The view (engine)

**Files:**
- `views.rs`: add `WorldMapView`, `WorldMapCell`, `WorldMapMark`,
  `WorldMapMarkKind` and `WorldMapRoute` beside the `FrameMap*` types
  (:2120).
  - The town kind carries the standing band, `SettlementKind`,
    `Option<Vitality>`, `Option<TownTrend>`, `Option<GrowthOutlook>`
    (Server), and the five flags.
  - The five flags come from `Standing::{sends_raiders, fields_patrols,
    preys_on_routes, refuses_service, allows_standing_route}`.
- `routes.rs`: add `corridor_chunks` (decision 9).
- `world.rs`: add `biome_at` (decision 3).
- `game/world_map.rs`: add `pub fn world_map(&mut self, center_chunk,
  radius) -> Option<WorldMapView>`.
  - It returns `None` unless `Locale::Surface`.
  - Revealed chunks are the stored set plus the derived set: chunks around
    the anchor, chunks around each outpost, and the route corridors.
  - Marks are filtered to revealed chunks.
  - Marks come from the existing calls: `outpost_marks`, `nest_positions`,
    the link source `compass_targets` uses, and `Settlements`.

**Tests:**
- The view is `None` underground and in base space.
- Derived reveals appear without being stored, and `ExploredChunks` is
  unchanged after the call.
- A known town in an unrevealed chunk is absent.
- A route's `preyed_by` equals `route_predators` for that route.
- `corridor_chunks` has a unit test, including a diagonal and negative
  coordinates.
- `Standings` is unchanged by the call (decision 4).
- A nest mark has `target: None`. Town, outpost, link and home marks carry
  the matching `CompassTarget`.

**Gate:** `cargo test -p feral-processes-engine`.

## Phase 3: Mode and keys (app-core)

**Files:**
- `lib.rs`:
  - Add `Mode::WorldMap`.
  - Add it to `is_battle`'s exhaustive list (:2325/:2489).
  - Add the `App` field `world_map_center`.
  - Add `WORLD_MAP_VIEW_RADIUS`.
  - Add a `world_map()` accessor that calls `Game::world_map(center,
    radius)`.
  - Add a helper for the side-list order: marks in view, nearest the party
    first. Gui and the key handler both call it.
- `app/playing.rs`: add the surface `g` branch (decision 12). It sets
  `world_map_center` to the party's chunk and `menu_selected = 0`.
- `app/menus.rs` (or a new `app/world_map.rs` if `menus.rs` is crowded):
  add `handle_world_map_key` (decision 11). `C` on a mark with no target
  returns the refusal as a row fragment, following the
  ability-unavailable string convention.
- `app/input.rs:372`: dispatch to it.

**Tests:**
- `g` opens `WorldMap` on the surface and `FrameMap` underground; this
  inverts the old test.
- Arrows move `world_map_center`, and `P` restores it.
- A letter selects a row.
- `C` on a town sets `CompassBearing`.
- `C` on a nest refuses and leaves the bearing unchanged.
- `Esc` returns to `Playing`.

**Gate:** `cargo test -p feral-processes-app-core`.

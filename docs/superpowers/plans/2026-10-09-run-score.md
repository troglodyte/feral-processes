## Decisions

1. **A kill is worth the frame's level in the Stack.** Wild foes carry no
   `Experience`. `ability_user_level` (`game/combat.rs:1323`) falls back to
   `wild_body_level()` = surface `ZoneLevel` (`game/spawning.rs:1625`),
   even in the Stack. For scoring only, add `Game::foe_score_level(e)`.
   - In the Stack, it returns the current frame's `FrameSpec::tier`
     (`stack.rs:293`).
   - Elsewhere, it returns `ability_user_level(e)`.
   - Combat is unchanged. Both kill sites call this helper.
2. **"Tier" is "depth" in this feature.** In the code, `tier` means
   `FrameSpec::tier`, which is a level. The card line is **"Deepest Stack
   depth"**, the field is `RunTally.deepest_depth`, and the constant is
   `SCORE_PER_DEPTH`. Depth counts 1..frames within one Stack.
3. **Bonus stat points are paid as unspent `StatPoints` after creation.**
   They are not added to the Points step budget.
   - `MAX_CREATION_STAT_POINTS` (`tuning.rs:78`) is untouched.
   - Pay them in `Game::grant_profile_rewards` (`game/lifecycle.rs:3513`),
     beside the `RandomMainStat` rewards.
   - The Points step shows "+N stat points from past runs, paid after
     creation".
4. **Bonus perk points ride the profile perk path.** They are added where
   `App::profile_perk_points` (`app-core/src/app/creation.rs:~1005`) feeds
   the perk picker. Confirm in source that this path reaches the picker
   allowance. If it does not, use `CharacterChoice::perk_points` instead.
5. **Bonus credits raise the basket budget only.**
   - Add `CharacterChoice.bonus_credits: u32` (default 0).
   - Add one pure fn `creation_credits(bonus) -> u32`. It replaces the
     hardcoded `CREATION_CREDITS` reads in engine `apply_creation_kit`
     (:301) and `creation_basket_cost` (:318), and in app-core
     `creation_credits_left` (:588) and `roll_kit_basket` (:129).
   - Keeping the class kit forgoes the bonus, and the step says so.
   - The arena's `CharacterSpec::choice()` defaults the field to 0, so the
     arena is unaffected.
6. **Banking is an engine call; app-core writes the file.**
   - Add `Game::bank_run_score() -> u64`. It computes
     `delta = card.total - tally.banked`, sets `banked`, adds `delta` to
     the engine's `Profile.lifetime_score`, and returns `delta`.
   - app-core adds `delta` to its own profile copy and calls
     `Profile::save` directly. Do not route this through
     `PendingProfileWrites`: `after_tick` is not reached on the game-over
     path.
   - **Death:** in `App::check_game_over` (`app-core/src/app/lifecycle.rs:687`),
     inside the `history_written` latch, **before** `seal_run`, so the
     sealed save carries `banked`.
   - **Escape:** in `App::escape_basin` (`app-core/src/app/ending.rs:41`),
     after the engine call.
   - **Abandon** (`App::leave_run`) is unchanged and banks nothing.
   - **Arena:** both paths already return early.
7. **The "Escaped" screen returns to play, not the menu.** The run
   continues after the ending. `close_ending` returns to `Mode::Playing`;
   the new screen sits between them.
8. **The player's manifest gets Tab faces: Stats ↔ Score.**
   - Program manifests keep Stats/Social/Talk.
   - `toggle_manifest_tab` (`app-core/src/app/inspection.rs:~350`) is gated
     by `is_owned_program` today. Add a player branch to it.
   - Add `ManifestTab::Score` (`app-core/src/lib.rs:1251`).
9. **One card builder, two outputs.** The manifest renders sections
   (`render/manifest_layout.rs`), not popup `Row`s.
   - One fn turns `ScoreCard` into `(label, count, points)` display lines.
   - Popup rows and manifest sections are both thin wrappers over it.
10. **What "compiled" counts.** Only decompiles (`decompile_body` :1324,
    `decompile_squad` :1490) count. `reinitialize_program` and breeding do
    not.
    - Both decompile sites call a new helper, `note_compiled()`. It does
      `note_deed(Deed::Tamed)` and `RunTally.compiled += 1`.
    - `history_summary`'s existing live "Programs compiled" text stays.
      ` Score: N.` is appended to it.
    - An escape without a later death writes no history line. That is
      existing behaviour; leave it.

## Phase A — engine: formula, tally, sites (engine only)

Files: new `crates/engine/src/score.rs` (+ `lib.rs` mod), `tuning.rs` (new
`SCORE_*` block beside "Achievement profile ceilings" :3519), `resources.rs`
(`RunTally`), `save.rs`, `game/lifecycle.rs`, `game/combat_rewards.rs`,
`game/sortie.rs`, `game/stack.rs`, `game/achievements.rs`, `resources.rs`
(`EnemyStrength::ordinal`).

1. `score.rs`: add `ScoreInputs`, `ScoreLine`, `ScoreCard`, `card()` and
   `creation_bonus()`. All are pure.
   - Tests: the arithmetic of each line, the multiplier for each mode and
     band, an all-zero card that keeps every line, each `creation_bonus`
     ladder's threshold and cap, and the spine test (fighter beats turtle
     under the live constants).
2. `RunTally` saved resource. Wire it like `FreeBuilds`: `SaveData` field
   behind `#[serde(default)]` (save.rs:1659), `sample_data` (:2368),
   `Game::load` insert (lifecycle.rs:1562), `Game::save` snapshot (:3265),
   `Game::new` setup (~:625).
   - Tests: a non-zero tally survives `game.save`/`Game::load` (copy
     `tests/drop_pods.rs:17`). An old save loads at zero (copy save.rs
     `a_save_without_the_enemy_strength_field_loads_at_standard`).
3. Tally sites, one red→green each:
   - `award_loot` (:804, beside the `RunFeats.kills` push :841): add
     `foe_score_level` to `foe_levels`, and `bosses += 1` when
     `is_boss_creature`.
   - `resolve_sortie_battle` dead-hostile loop (sortie.rs:503-526): sum
     `foe_score_level` for dead hostiles only.
   - The `note_compiled()` helper at both decompile sites.
   - `achievement_system` (:89): `achievements += 1`. If clippy flags
     `too_many_arguments`, bundle the params as `RunStanding` does.
   - `enter_frame` (game/stack.rs:544): `deepest_depth = max(...)`, so an
     ascent does not lower it.
4. `Game::score_card()`. It reads `PhaseKeys::count()` from the player,
   counts `Structure` entities for structures standing, takes `escaped`
   from `PhaseKeys.story_complete`, and reads mode and band. Append
   ` Score: N.` in `history_summary` (:3446), with a test.
5. `Profile.lifetime_score: u64` with `#[serde(default)]`
   (`achievements.rs:211`). Add `Game::bank_run_score()` (decision 6).
   - Tests: a profile round trip, and an old profile that keeps its
     achievements.
   - Bank tests: a death banks the total. Escape then death banks exactly
     the total overall. A second bank with no change banks 0.

Gate: run `cargo test -p feral-processes-engine`, then `balance_sim`.
Expect no curve movement, because balance_sim is pure math and never runs
creation.

## Phase B — banking calls, creation bonus (engine + app-core)

Files: `app-core/src/app/lifecycle.rs`, `app-core/src/app/ending.rs`,
`app-core/src/app/creation.rs`, engine `game/creation.rs`,
`game/lifecycle.rs` (`grant_profile_rewards`).

1. Bank at death and at escape (decision 6), with app-core tests:
   - a death writes `lifetime_score` to the profile file (use a temp path
     unique to the test);
   - escape then death sums to the card total;
   - an abandon leaves the file unchanged;
   - a Forgiving escape banks once.
2. Stat bonus in `grant_profile_rewards` (decision 3).
3. Perk bonus (decision 4).
4. Credit bonus: the `bonus_credits` field and `creation_credits()` at all
   four sites (decision 5).
5. Creation tests: a profile with a lifetime score raises unspent
   `StatPoints`, the perk allowance and the basket budget by
   `creation_bonus`'s amounts. A profile without the field gives none. The
   arena's creation gets none.

Gate: run `cargo test -p feral-processes-engine -p feral-processes-app-core`.

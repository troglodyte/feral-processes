# Farms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff tend player-marked farm plots on the base with no further orders: dimple each tile, let it grow through visible stages, harvest one product item per tile onto the floor, replant, forever.

**Architecture:** A plot is a `FarmPlot` entity (the recipe) owning per-cell `FarmTile` entities (base-space `Position` + growth), the `DigSite` precedent one level up. Crops are data in `assets/crops/`, loaded by a `CropDb`. Growth advances on the base-labour clock in `turn.rs`; dimple and harvest are one new task kind, `TaskKind::Tend(FarmJob)`, whose wants are appended after `dig_wants` and worked by a `&mut Game` crew step modelled on `run_dig_crew`.

**Tech Stack:** Rust, standalone `bevy_ecs` (engine), app-core `App`/`Mode`, gui `Painter`, RON assets and saves.

**Spec:** `docs/superpowers/specs/2026-10-16-farms-design.md` — authoritative, including "Settled after the builder check". Read it before any task.

## Review Focus

1. **Recipe changed (or tile unmarked) while a worker is mid-harvest** — the labour is dropped, no item spawns, the worker is free next pass. Pinned: Task 5 `a_recipe_change_mid_harvest_drops_the_labour_and_spawns_nothing`.
2. **A new box drawn over part of an existing plot** — existing tiles keep their plot, recipe and growth; only uncovered eligible tiles form the new plot. Pinned: Task 2 `a_box_over_an_existing_plot_leaves_its_tiles_where_they_were`.
3. **Something built on a growing tile** — only that tile leaves the plot; the rest keeps growing; nothing is spawned. Pinned: Task 3 `a_build_request_on_a_plot_tile_removes_only_that_tile`.
4. **The crop's mod is removed between save and load** — plot loads unsown, all tiles fallow, warning logged, `[c]` can set a recipe again. Pinned: Task 4 `a_plot_whose_crop_is_gone_loads_unsown_with_a_warning`.
5. **A base whose only instruction is a farm** — the quiet-base early return must not strand a tender on a finished tile; it moves on to the next. Pinned: Task 5 `a_farm_alone_keeps_its_tender_moving_between_tiles`.

### Task 2: Plots — model, marking, recipe, view

**Files:**
- Create: `crates/engine/src/game/base/farm.rs`, `crates/engine/src/tests/farms.rs`
- Modify: `crates/engine/src/components.rs` (beside `DigSite`), `crates/engine/src/views.rs` (beside `DigMark`), `crates/engine/src/game/base/mod.rs` (`pub(crate) mod farm;`), `crates/engine/src/tests/mod.rs` (`mod farms;`)

**Decision — component shape.** A `FarmPlot` entity holds the recipe; each cell is a `FarmTile` entity with a base-space `Position` pointing at its plot. Per-cell entities because a `Task` targets one `Entity` (the `DigSite` precedent — the crew's target is the cell); a plot entity because "one box is one plot, one recipe" must be one write, and an `InteractionKind` needs a `Copy` handle for the plot. `DigSite` is not extended: its `marked`/`Durability`/finish semantics are a different verb, and every dig reader would need a farm filter. Plot entities carry no `Position`; tile entities carry no `Glyph` (the renderer draws them from the view, like dig marks).

**Decision — overlapping boxes.** The anchor decides, as `toggle_mark_box`: anchor on a plot tile → **clear** every plot tile in the box (whatever plot owns it); otherwise → **mark**: one new plot from the box's eligible cells that are *not already plot tiles*. Existing tiles never change plot. A plot left with zero tiles is despawned; a mark pass with zero eligible new cells spawns nothing.

**Decision — eligibility.** Laid floor only (`BaseGrid::is_floor`), not in `structure_tiles()`, not in `build_site_tiles()`. A floor pile does not block; a finish mark may coexist. Ineligible cells are skipped.

**Interfaces:**
- Produces (components.rs):
  - `#[derive(Component, Clone, Debug)] pub struct FarmPlot { pub recipe: Option<CropId> }`
  - `#[derive(Component, Clone, Copy, Debug)] pub struct FarmTile { pub plot: Entity, pub growth: CropGrowth }`
  - `#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)] pub enum CropGrowth { #[default] Fallow, Growing { elapsed: u32 }, Ripe }`
- Produces (views.rs):
  - `#[derive(Clone, Debug, PartialEq, Eq)] pub struct FarmTileView { pub pos: (i32, i32), pub plot: Entity, pub crop: Option<(String, GlyphColor)>, pub state: FarmTileState }` — `crop` is the recipe's glyph and colour, `None` when unsown.
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum FarmTileState { Fallow, Growing { stage: u8, stages: u8 }, Ripe }` — `stage` in `0..stages`.
- Produces (farm.rs, `impl Game`):

  - `pub fn set_plot_recipe(&mut self, plot: Entity, crop: &CropId) -> Result<(), String>` — refuses a non-plot entity or an unknown crop; the same recipe again is a no-op (keeps growth); a different one sets every tile `Fallow` and frees nothing itself (Task 5's crew step notices).

**Decision — clock.** `grow_farms` runs immediately **before** `schedule_base_labour()` in `tick_inner`, with `run_dig_crew`'s guard (`is_game_over` / `has_active_battle` → return). Before, so a tile that ripens this tick is a want this tick. No catch-up.

- Test: `crates/engine/src/tests/farms.rs`, `crates/engine/src/tests/duties.rs`

**Decision — one task kind with a job.** `TaskKind::Tend(FarmJob)` with `#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)] pub enum FarmJob { Dimple, Harvest }`. One variant keeps most matches to a single `Tend(_)` arm; the job is carried so the crew step can tell the work it was posted for from the tile's current state, which is how a recipe change mid-labour drops it. `TaskKind::ALL` gains both (`[TaskKind; 6]`). `phrase`: "dimpling phase space" / "bringing in a harvest". Additive to `MemorySubject::Activity`'s RON — no bump.

**Decision — duty column.** `Tend(_)` is admitted by `Duty::Dig` only. No new column (spec: no role filter); plots are drawn in the Excavation plan, so the DIG column is the one a player already reads as "base-grid work".

**Decision — non-structure kind everywhere `Excavate` is.** Treat `Tend(_)` like `Excavate` at each site: footprint 1 in `reaches`; included in the pre-matching unreachable drop but **silently** (no announcement, no latch — notifications are not required); included in the `can_walk_to_post` check; `post_desc` structure `None`; `refuses_post` never refuses it; not saved as a cronjob (lifecycle filter, `unreachable!` arm extended); not "attended" in inspection; `wears_job_mark` as a digger does; status line "tending the plot at x, y" (trade.rs / work_orders.rs ~2713 style); gui labels "Tending".

**Interfaces:**
- Consumes: Tasks 2–3.
- Produces:

  - `pub(crate) fn farm_wants(&mut self) -> Vec<(Entity, TaskKind)>` — tiles of sown plots only: every `Ripe` tile as `Tend(Harvest)`, then every `Fallow` tile as `Tend(Dimple)`, each block in `(x, y)` order (harvest first: it is the one that pays out), filtered by `hauling::has_station(grid, pos, 1, &structure_tiles)` exactly as `dig_wants`.

  - `pub(crate) fn post_tender(&mut self, worker: Entity, tile: Entity, job: FarmJob)` — `post_digger`'s shape (`required` = the job's tuning constant); dispatched from the posting match.

Any mismatch, a despawned tile, or an unsown plot → remove the `Task` and spawn nothing. On a completed landing, remove the `Task` too (the job is done; the scheduler re-posts).

# Game menu — plan

Spec: `docs/superpowers/specs/2026-10-22-game-menu-design.md` (read it; this
plan does not restate it). Three crates (engine, app-core, gui), new
`profile.ron` fields behind `#[serde(default)]`, no save-format change. Read
`.claude/rules/seams-screens.md` (hub rule) and `seams-hud.md` before P2/P3.

## Decisions (builder's calls, made here)

- **Hub:** `Hub::GameMenu`, `HubKind` in new `app/game_menu.rs`. Pages, in
  order: **Gameplay**, **Audio**, **Graphics**, **Save & quit** (last, only
  while `app.game.is_some()`). `table()` empty; `pages(&App)` builds the
  list. `remembers() = false` (a remembered Save page would not exist from
  the main menu). `leave`: `Mode::Playing` if a run is live, else
  `Mode::MainMenu`. Verify every path to `MainMenu` clears `game` (arena's
  `leave_arena` is the one to check); if one doesn't, store the origin on
  `open` instead of reading `game`.
- **Modes:** `Mode::Options` → `Mode::GameplayOptions`; add
  `Mode::AudioOptions`, `Mode::GraphicsOptions`; `Mode::QuitRunConfirm` stays
  as the Save & quit page (rewrite its doc). Update gui's all-modes list
  (`render/mod.rs` ~1942) and `input.rs` dispatch.
- **Rows:** `option_rows()` answers for the current mode. `OptionKey` gains
  `Volume`, `Effects`, `PerfOverlay`; `OptionRow` gains a kind
  (`Toggle` / `Level`). Enter flips a toggle. Left/Right step a `Level` row
  by 10 — claimed in `App::screen_claims` (the seam's one place) only when
  the cursor is on a `Level` row, so Left still reaches the rail elsewhere.
  One write path: `toggle_option` generalises to `set_option` (mutate →
  `profile.save` → status line on error), the in-memory value kept either way.
- **Profile fields** (`crates/engine/src/achievements.rs`, flat, plain types
  per the struct's own rule): `volume_percent: u8` (default 20 =
  `DEFAULT_VOLUME`; integer so 10% steps can't drift; clamp ≤100 on read),
  `effects: bool` (default true, needs a default fn like
  `tactical_battles_default`), `perf_overlay: bool` (default false).
- **Reload trap:** pure `Profile::keep_settings_from(&mut self, &Profile)`
  copies the four settings. Called at every site that replaces `App.profile`
  (`app/lifecycle.rs` ~318, ~370, `flush_profile_writes` ~692) so the
  in-memory value wins.
- **Tactical live:** `Game::set_tactical_battles(bool)` writes the `Profile`
  resource's field; `set_option` calls it when a run is live. Rewrite the
  stale "main menu only" doc comment.
- **Save & quit page:** three rows — Save (stay in menu), Save and quit
  (`save_game` false → stay with the error, as now), Quit without saving →
  an inline yes/no (`App` flag; `screen_claims` takes Esc while it's up).
- **Esc on the map:** watching → release (unchanged); then any Esc arm
  `handle_playing_key` already has; only a bare Esc opens the hub. Delete the
  `'q'` arm. `[s]` stays.
- **Volume toast:** dropped (the value is on screen). Delete `draw_toast` /
  `fe.toast` if nothing else sets it.

## P1 — engine (TDD, one commit)

Tests in `crates/engine/src/tests/achievements.rs`: an old `profile.ron`
string without the new fields loads with defaults (and keeps `earned`);
round-trip of non-default values; `keep_settings_from` copies exactly the
four settings and nothing earned; `set_tactical_battles` changes
`game.profile()`. Then the fields, fn and method.

## P2 — app-core (TDD, commit per green step)

Move/extend `tests/options.rs` and `tests/quitting.rs`; new cases:
- Esc on map opens the hub on Gameplay; Esc while watching only releases;
  `q` on the map does nothing; `[o]` from main menu opens it without the
  Save page; rail Esc returns to map / main menu respectively.
- Volume Left/Right step and clamp 0/100, write `profile.ron`; Left on a
  toggle row still goes to the rail; `[`/`]` turn pages.
- Toggles for effects/overlay persist; tactical toggle mid-run reaches
  `game.profile()`.
- A profile flush mid-run (earn something) doesn't revert a just-changed
  setting; a failed profile write keeps the in-memory value + status line.
- Save page: save stays; save-and-quit leaves; failed save holds with error
  (existing test, re-pointed); quit-without-saving needs the confirm, Esc
  backs out of the confirm without leaving the hub.
- Hub nav sanity: `hub_for` finds each page; no orphan mode left.

New mode logic lives in `app/game_menu.rs`, not `lib.rs`.

## P3 — gui (one commit)

- `crates/gui/src/lib.rs`: delete `fe.volume`, `fe.perf_on`, `DEFAULT_VOLUME`,
  the `volume_keys` block, `\` and `F3` handlers; read volume/effects/overlay
  from the app's profile each frame (`fe.fx.enabled` set from it or removed).
  The gui writes none of them. Fix the "GUI-only concerns" comment.
- Draw the three options pages and the save page through the existing hub
  page frame (`render/base_report/mod.rs::draw_hub_page` is the model);
  `render/meta.rs` `draw_options` / `draw_quit_run_confirm` become page
  bodies. Volume row shows `◀ 40% ▶`-style value. Update the existing
  `draw_options` shape test (~`render/mod.rs:2593`).
- `render/hud/log_frame.rs:329`: `keycap("q","menu")` → `keycap("Esc","menu")`.
- Screenshot check: `cargo run -- --template stack --keys "Escape" --screenshot
  …` and one with `Escape Down Right Right` (volume); Read the PNGs.

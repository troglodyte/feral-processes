# FTUE — implementation plan

Spec: `docs/superpowers/specs/2026-10-30-ftue-design.md` (read it first; this
plan does not repeat its reasoning). Three crates + save format → full gate,
final whole-branch opus review.

**Setup:** ask the user before creating a worktree/branch (they play from the
primary checkout). Branch `ftue`. Commit per green step. Never push, never
`git checkout`/`stash` over uncommitted work, stage explicit paths.

## Shape (interfaces, not finished code)

`crates/engine/src/ftue/` — `mod.rs` (types, decide), `entries.rs` (the
list — the one file the user edits), `tests.rs`.

```rust
pub enum FtueEvent { BaseFounding, FirstDescent, FirstRaid, FirstTownRaid,
    FirstWorkOrder, LowPower, DownedProgram, FirstStatic, LearnedImage }
pub enum FtueTrigger { Research(&'static str), Built(&'static str),
    Crafted(&'static str), Event(FtueEvent) }
pub struct FtueEntry { pub on: FtueTrigger, pub title: &'static str,
    pub body: &'static str, pub sprite: Option<&'static str>,
    pub glyph: char, pub color: GlyphColor }      // mirror NotificationDef
pub const ENTRIES: &[FtueEntry];                   // in entries.rs
impl FtueTrigger { pub fn key(&self) -> String }   // "research:x", "built:x",
                                                   // "crafted:x", "event:first_raid"
pub fn entry_for(t: &FtueTrigger) -> Option<&'static FtueEntry>;

// pure decide step
pub struct FtueGuidance { pub enabled: bool, pub never: Vec<String> } // Profile
pub enum FtueDecision { Show, LatchOnly, AlreadyShown }
pub fn decide(key: &str, run_shown: &BTreeSet<String>, g: &FtueGuidance) -> FtueDecision;
```

- `Game::ftue(trigger)` / `Game::ftue_filled(trigger, fills, detail)`:
  no entry → just latch the key in the run set (see Phase 2.5); else `decide`; `Show` queues a `Notification`
  (with `ftue_key: Option<String>` added so app-core knows to offer D/T);
  `Show` and `LatchOnly` insert into the run set.
- Run set: `BTreeSet<String>` per-run state, saved in `SaveData`
  (`save.rs`), bump `SAVE_FORMAT_VERSION`; old saves → empty.
- Profile: `ftue: FtueGuidance` (`#[serde(default)]`, `enabled` defaults
  **true**); writes via `PendingProfileWrites` (new fields) or an app-core
  profile mutation — follow whichever path the D/T keys can reach.
- `Game` API for app-core: `ftue_never(key)`, `set_guidance(bool)`,
  `reset_guidance()` (enabled + clear `never`), `guidance_enabled()`.

## Phase 1 — engine core (engine only)

1. `ftue/` types, `key`, `decide` + direct tests of `decide`
   (all three outcomes; disabled → LatchOnly; never → LatchOnly; shown →
   AlreadyShown).
2. Profile field + load of a pre-change `profile.ron` still parses
   (keeps achievements).
3. Run set on save: save→load test (not just RON round-trip); version bump.
4. `Game::ftue*` + Notification `ftue_key`; test: fires once per run,
   again after a fresh `Game`, not after save→load.
5. Census tests: every `FtueEvent` has exactly one entry; keys unique;
   every `Research`/`Built`/`Crafted` id exists in the loaded research /
   structure / item dbs.

Gate: `cargo test -p feral-processes-engine ftue notifications save`.

## Phase 2 — triggers and the tutorial port (engine only)

1. Port the 9 `OnceEver` kinds: move title/body/sprite/glyph/colour
   verbatim into `entries.rs` as `Event(..)` entries; call sites switch
   from `notify(NotificationKind::X)` to `ftue(Event(X))` (keep fills).
   Delete the variants, their `def`/`latch_key` arms, `Repeat` (if only
   `Always` remains, delete the enum and the field), `Profile::see`,
   `seen_notifications`, `PendingProfileWrites.seen`. Verify serde ignores
   the retired `seen_notifications` field in an old `profile.ron` (test).
   Update `tutorials_latch_and_milestones_do_not` and other notification
   tests (`tests/notifications.rs`, `extraction.rs`, `environment.rs`,
   `turn.rs`, `building.rs` users).
2. `Research`: in `grant_research` (`game/unlocks.rs`), after the
   `ResearchComplete` notify.
3. `Built`: `complete_new_build` (`game/base/construction.rs`) and the
   instant-placement path in `place_structure` (`game/base/building.rs`).
   Not upgrades.
4. `Crafted`: hand craft (`game/crafting.rs` completion), work orders
   (`settle_orders`), assembler (`systems.rs` assemble — bevy system, no
   `Game`: push item id to a resource drained by `Game` after the tick,
   sorted, the low-Power pattern).
5. Hook tests: `Game::ftue` inserts the trigger's key into the run set
   **even when no entry exists** (harmless, and it makes every hook
   observable without a shipped entry). Each hook's test asserts the key
   lands in the run set via a `&self` query (`ftue_shown(key) -> bool`).
   Mutation-check one hook. (Change `Game::ftue` in Phase 1 to match.)

Gate: `cargo test -p feral-processes-engine`, `balance_sim`, clippy.

## Phase 3 — app-core + gui

1. `handle_notification_key` (`app/lifecycle.rs`): when the pending
   notification has `ftue_key`, `D` → `ftue_never`, `T` →
   `set_guidance(false)`, then dismiss as Enter. Ensure profile write
   reaches disk (existing persist path, `lifecycle.rs:~651`).
2. Options screen: guidance on/off row + "show all again" row
   (lists are highlight + Enter). New logic in `app/<module>.rs`, not
   `lib.rs`.
3. gui `render/notify.rs`: key hint line `[Enter] Dismiss  [D] Don't show
   again  [T] Turn off guidance` only for FTUE popups; hint case matches
   handler case; check `D`/`T` aren't raw keys firing in every mode;
   the tallest-notification-fits test covers FTUE entries + hint line.
4. Hold-`?` shortcut sheet: add the popup's keys if that sheet lists
   Notification mode.
5. Screenshot check: `--template` + `--keys` to trigger a popup if a
   reachable one exists; Read the PNG.

Gate: `cargo test --workspace`, clippy `--all-targets`, fmt.

## Phase 4 — docs and seams

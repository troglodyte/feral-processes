# Tactical props: structures, destructible cover and explosions

The tactical battle map is per-cell noise over four kinds (`Open`, `Rough`,
`Cover`, `Blocked`; `crates/engine/src/tactical/map.rs`). It has no walls,
no chokepoints and nothing that reads as a place. This change stamps
authored derelict high-tech set pieces onto the noise, lets any combatant
destroy the cover someone hides behind, makes some of it explode, and ships
new art for all of it.

## Decisions

| Question | Decision |
|---|---|
| Layout | Data prefabs: `.ron` grids in `assets/battle-props/`, stamped onto the existing noise by seed. No procedural wall/room pass. |
| Representation | A prop layer on `Board` (approach A), not new `BattleCell` kinds and not inert bodies. |
| Destructibility | Per piece in data: `hp: Some(n)` or indestructible. |
| Explosions | Visual on every destruction; `volatile` pieces also blast nearby cells for damage. |
| Art | 16x16 near-white PNGs generated by `scripts/battle-props.py`; redrawable in the Sprite Forge. |
| Scope out | Siege boards (built by flood fill, saved in `SiegeSave`) get no props. Arena files cannot pick a map. |

Rejected:

- **New `BattleCell` kinds + HP table** — `BattleCell` is saved in
  `SiegeSave`, so it is a save-format change, and the four kinds are a
  documented complete 2x2 (cross it × see through it).
- **Props as inert bodies.** Sieges already seat structures as bodies and
  route swings at them to `Game::damage_structure`
  (`tactical/turn.rs`, `tactical_attack`). That works for one structure kind
  in one battle mode; generalising it puts every body census (victory, XP,
  morale, initiative, squads, `deploy::plan`) one missed filter away from
  XP for shooting a crate or a battle that never ends.
- **Procedural walls/rooms** — less authored character, not moddable as
  files. Can be added later as another placement pass.

## Data: `assets/battle-props/`

Two subdirectories, one `.ron` per file: `prefabs/` and `pieces/`, loaded by a `PropDb::load_dir` that follows the
existing `*Db::load_dir` pattern (malformed file → logged warning, skipped).
Schema documented in `assets/battle-props/README.md`.

```ron
(
    id: "collapsed_rack_row",
    biomes: [Backplane, Deadlock],   // empty = every biome
    weight: 3,
    rows: [
        "RR.R",
        "..c.",
    ],
    legend: { 'R': "server_rack", 'c': "power_cell" },
)
```

`.` is "leave the noise alone"; a legend entry naming an unknown piece
skips the prefab with a warning. A piece, in `pieces/`:

```ron
(
    id: "server_rack",
    blocks_move: true,
    blocks_sight: true,
    cover: true,            // counts for cover_between
    hp: Some(30),           // None = indestructible
    armour: 2,
    volatile: None,         // or Some((radius: 1, damage: 12))
    leaves: Rubble,         // Rubble | Floor
    sprite: "prop_server_rack",
    decoration: false,
)
```

Every new field is `#[serde(default)]`. Decoration pieces
(`decoration: true`) never block or take damage; they are visual only.

## Engine: the prop layer

`Board` gains `props: BTreeMap<(i32, i32), PropCell>` where `PropCell`
holds the piece id, current HP and flags copied from the def at placement
(the board stays self-contained; no `PropDb` lookup during reach queries).
Like `screens`, it is an overlay: the base `cells` are untouched.

The one-place rule: **`Board`'s per-cell movement-cost read (added if absent), `Board::blocks_sight`
and the cover read in `reach::cover_between` consult props.** Every
existing caller (`movement_field`, `path_to`, `line_of_sight`,
`aim_in_sight`, `shape_cells`, the AI's `cover_share`) goes through those,
so none of them changes. Where a caller reads `BattleCell` directly instead
of the `Board` method, the plan converts it to the method — the plan's
first task is that census.

Rubble is a prop, not a cell kind: `blocks_move: false`, movement cost
`TACTICAL_ROUGH_COST`, no cover, not destructible.

`Board` is not saved for ordinary battles and siege boards get no props,
so **no save-format change**.

### Placement

`map::generate` gains a pass after the noise and before
`carve_to_connect`:

1. Count from `side` (named constants in `tuning.rs`, e.g. 14 → 1–2
   prefabs, 28 → 4–6).
2. Pick prefabs by weight from those whose `biomes` include `spec.biome`,
   seeded from the same hash fold the noise uses (no RNG resource touched).
3. Place each at a hashed position and rotation; reject overlaps with each
   other and with the deploy edges.
4. Scatter decoration on `Open` cells at a low per-biome density.
5. `carve_to_connect` then treats prop cells that block movement as
   unwalkable, and may delete a destructible prop to connect the sides;
   it never deletes an indestructible one in preference to noise.

`deploy::plan` runs after, so nothing deploys on a prop.

## Engine: fighting the terrain

- **Swing:** `Game::tactical_attack_prop(cell) -> bool`. Same reach rule
  (`reach::swing_reaches` with the prop's one cell as the target
  footprint), same action cost. Damage = `swing_damage(actor)` minus
  `armour`, minimum 1. No hit roll, no XP, no morale.
- **Routines:** every damaging routine's affected cells
  (`shape_cells`) damage any destructible prop on them. Line/Cone already
  stop at the first sight-blocking cell; that cell is now included in the
  hit set when it holds a prop, so a beam breaks the cover it is stopped by.
- **Destruction:** HP 0 removes the `PropCell`, places `leaves`, and cues
  `TacticalFxKind::PropDestroyed { volatile }` on the existing
  `TacticalFxQueue` (`resources.rs`), drained by `Game::take_tactical_fx`
  — the seam rule's pattern, not a new event list. A `volatile` blast resolves through the same radius
  damage path a radius routine uses, hitting bodies and props; chained
  blasts are capped at `TACTICAL_PROP_CHAIN_MAX` depth.
- **AI** (`tactical/ai.rs`): two new candidates in the existing scoring,
  no new mode:
  - *Break cover* — no hostile in sight, a destructible prop is what blocks
    the best sight line, and repositioning cannot get a shot.
  - *Detonate* — a volatile prop in reach whose blast covers hostile
    bodies, scored by expected blast damage against the best ordinary
    attack.

## View and app-core

- `TacticalView` exposes props as `(cell, sprite key, hp, max_hp,
  volatile, decoration)`; destruction reaches gui through
  `take_tactical_fx`.
- The attack target cursor in `crates/app-core/src/app/tactical.rs` can
  select a prop cell; the readout shows its HP and an "explosive" tag on
  volatile ones. Key bindings follow the existing attack flow (actions
  UPPERCASE, lowercase letters are row selectors).

## Renderer

`crates/gui/src/render/tactical.rs`, drawing only through `Painter`:

- Props draw after ground, before bodies. Sprite `prop_<piece>`, and
  `prop_<piece>_cracked` below 50% HP when that sprite exists.
- Decoration draws dimmed so it reads as background. Hue rule from the
  ground-textures spec holds: props spend brightness and a muted cast,
  never a wash hue.
- A destruction event plays the existing `explosion` effect; volatile ones
  play a new `assets/effects/explosion_large.ron` (bigger radius, more
  shake).

## Art

`scripts/battle-props.py`, in the style of `scripts/ground-tiles.py`,
writes near-white 16x16 PNGs to `assets/sprites/`. Starter set:

- Cover/structure: server rack, cracked hull plate, collapsed pylon, dead
  drone chassis, conduit wall (straight, corner, broken).
- Volatile: power cell, coolant tank.
- Rubble.
- Decoration: cable run, scorch mark, glass shards, dead screen.
- A `_cracked` variant for each destructible piece.

Starter prefabs (6–8): wall run with a one-cell gap (chokepoint), L-shaped
hull wreck, rack row, crashed drone with a power cell, pylon fallen across
the map, coolant tank cluster.

The prop sprites are added to the Sprite Forge picker list
(`load_static_sprite_subjects`), so they can be redrawn there.

## Testing

- Generation stays deterministic: same spec → same board, props included.
- Both sides connected after placement, across many seeds and every biome.
- A census test: props appear on every biome a fight opens on.
- A prop blocking sight: `line_of_sight` false; destroy it, true.
- Rubble costs `TACTICAL_ROUGH_COST` and gives no cover.
- Volatile chain terminates at `TACTICAL_PROP_CHAIN_MAX` and damages bodies
  in radius.
- AI breaks a blocking prop / detonates a volatile one in constructed boards
  (`Board::from_rows` gains a prop marker for tests).
- Malformed prefab `.ron` is skipped with a warning.
- `balance_sim` run; expected unchanged — any moved curve is investigated, not accepted.
- A screenshot through the arena (`FERAL_DEV_ARENA=1`) confirms the art
  reads on screen.
